# ADR-0016: 워크로드별 AI 모델 선정과 신고 초안 생성 경로

- **Status**: Accepted (2026-11-26 — 리뷰: 김세혁)
- **Date**: 2026-11-26
- **Deciders**: 안성일(AI/Guardrail — 라운드 승인 · 선정 판단)
- **Refs**: #648(모델 선정 근거) · #623(신고 초안 생성 계약) · PR #672(선정 모델 적용)

## Context (배경)

세 작업이 모델 하나를 쓰고 있었다. SecOps는 보안 인시던트를 분석하고, FinOps는 비용 절감 후보를 분석한다. 절감 단가 조회에서는 모델이 단가를 제시하고 최종 절감액은 서버가 계산한다. 기존 모델 `gpt-5.6-luna`를 교체하려면 세 작업 각각에서 품질, 호출 비용, 응답 시간을 비교해야 했다.

신고 초안에는 기존 모델이 없었다. 서버가 모은 사실만으로 사건 경위와 대응 내용을 쓸 수 있는지, 사용자가 요청한 자리에서 완성된 초안을 받을 만큼 생성 시간이 짧은지가 선택 기준이었다.

## Decision (결정)

네 작업 모두 `gpt-6-luna`를 사용한다. 모델이 추론에 들이는 노력의 수준(`reasoning effort`)은 분석 세 작업에서 `low`, 신고 초안 서술에서 `high`로 정했다. 신고 초안은 전용 모델을 설정한 경우에만 생성한다.

### 1. 비교 조건은 유료 실행 전에 고정한다

유료 실험을 시작하기 전에 비교할 모델과 설정, 모델에 줄 지시문(프롬프트), 시험 사례와 정답, 통과·선정 기준, 코드 버전과 단가를 고정했다. 답변을 채점할 두 모델(Claude Opus 5.5, GPT-6.1 Sol)이 이 조건을 검토하고 안성일이 실행을 승인했다. 실험에 앞서 실제로 응답한 모델이 요청한 모델과 같은지도 확인했다.

두 채점 모델은 같은 답변을 따로 읽고, 전체 점수가 아니라 **채점 항목별로** 판정을 대조했다. 의견이 갈린 항목은 안성일이 검토했다. 절감 단가는 서술이 아니라 수치이므로 정답의 허용 오차 안에 드는지로 판정했다.

### 2. 분석 세 경로 — `gpt-6-luna` low

**기준선**은 기존 모델을 후보와 같은 조건에서 다시 측정한 값이다. 보통 걸리는 시간은 중앙값(p50), 느린 쪽의 응답 시간은 95백분위수(p95)로 표시한다. p95가 6초라면 실행의 약 95%가 6초 안에 끝났다는 뜻이다. 비용은 캐시 할인을 적용하지 않고 입력과 출력에 고정 단가를 곱해 추정한 모델 호출당 금액이다. 채점 비용은 제외했으며 실제 청구액과는 다르다.

**교체 규칙:** 후보가 품질을 통과하고, 비용과 p95가 **둘 다** 기준선 이하일 때만 교체한다. 조건을 만족하는 후보가 여럿이면 가장 저렴한 모델을 쓴다. 기존 모델부터 품질 미달이면 통과한 후보 중에서 담당자가 선택한다. [11월 17일 분석 모델 비교 결과](https://github.com/ProjectVigilantis/vigilantis/issues/648#issuecomment-6933899215) 중 기준선과 최종 선택은 다음과 같다.

| 작업 | 모델과 추론 수준 | 품질 | 추정 비용(달러/호출) | p50(초) | p95(초) |
| --- | --- | --- | --- | --- | --- |
| SecOps 분석 | 기준선 `gpt-5.6-luna` low | 98/100 통과 | 0.00160 | 4.936 | 5.929 |
| SecOps 분석 | `gpt-6-luna` low | 97/100 통과 | 0.00074 | 3.805 | 6.187 |
| FinOps 분석 | 기준선 `gpt-5.6-luna` low | 통과(60회 중 실패 0) | 0.00063 | 6.163 | 7.089 |
| FinOps 분석 | `gpt-6-luna` low | 통과(60회 중 실패 0) | 0.00028 | 5.403 | 7.033 |
| 절감 단가 조회 | 기준선 `gpt-5.6-luna` low | 59/60 미달 | 0.00041 | 2.756 | 5.238 |
| 절감 단가 조회 | `gpt-6-luna` low | 60/60 통과 | 0.00016 | 2.575 | 4.105 |

지연은 SecOps·FinOps에서는 그래프 실행 한 건, 절감 단가에서는 조회 한 건의 경과 시간이다. FinOps의 비용은 그래프 실행 60회에 든 모델 호출 120회를 기준으로 한다.

- **SecOps — 결과를 본 뒤 허용한 예외.** 사전 규칙의 결론은 기준선 유지였다. 두 모델 모두 각 사례에서 10회 중 8회 이상 통과했고 후보의 비용은 기준선의 약 46%였다. 응답 시간은 중앙값이 **1.131초 짧아진 반면 p95는 0.258초 길어졌다.** 안성일은 중앙값이 줄었고 p95 비교가 모델마다 100회씩 측정한 한 차례의 실험에 근거한다는 점을 고려해, 이번에 한해 p95 초과를 허용했다. 이 예외로 세 작업의 모델을 통일했다. 품질 통과 수는 선정 모델이 기준선보다 1건 적었다(97/100 대 98/100).
- **FinOps — 규칙에 따른 교체.** 두 모델 모두 60회 동안 요약 내용이 입력 사실과 어긋난 경우가 없었고 나머지 품질 기준도 통과했다. 후보의 비용과 p95가 모두 기준선보다 낮았다.
- **절감 단가 — 기준선 품질 미달 시의 선택.** 품질 기준은 조회 60회 모두 허용 오차 안에 드는 것이다. 기준선은 1회 벗어났다. 안성일은 60회 모두 통과한 후보 중 가장 저렴한 `gpt-6-luna` low를 골랐다. p50과 p95도 기준선보다 짧았다.

### 3. 신고 초안 — 서버가 사실을 제공하고 모델은 근거를 인용해 서술한다

**무엇을 통과해야 하는가.** 후보를 추릴 때는 각 사례에서 10회 중 8회 이상 통과하고 안전 위반이 없는 조합끼리 호출 비용을 비교했다. 최종 확인에서는 시험용으로 구성한 사건 9개를 각각 30회씩 실행했다. **모든 사건에서 24회 이상 통과하고, 270회 전체에서 안전 위반이 한 건도 없어야 했다.**

**어떤 조합을 골랐는가.** 추론 수준 `medium`은 채점 오류를 고쳐 기존 답변을 다시 채점했을 때는 통과했지만 다음 실험에서 그 결과가 재현되지 않았다. `gpt-6-luna`를 `high`로 설정해도 초안의 문장에 근거 없이 ‘GuardDuty’라는 탐지 서비스 이름을 붙인 경우가 3건 있었다. 그래서 **같은 문장에 GuardDuty 관련 사실을 인용할 때만 그 이름을 쓰도록** 지시문을 수정했다(실험 기록의 `P4`). [11월 19일 최종 확인](https://github.com/ProjectVigilantis/vigilantis/issues/648#issuecomment-7003784942)에서 이 조합은 270회 중 268회 통과했다. 통과 수가 가장 적은 사건도 30회 중 28회였고, 안전 위반은 없었다.

**누가 무엇을 쓰는가.** 서버는 인시던트·증거·감사·조치 실행·알림 발송 기록에서 사실을 모아 식별 번호를 붙인다. 확인된 값에는 그 의미를, 미확인 값에는 사유를 담아 모델에 보낸다. 모델은 사건 경위와 대응 내용만 쓰고 문장마다 근거가 된 사실 번호를 인용한다. 서버가 확인하는 것은 *이번 요청에 그 번호가 있는지*까지다. *그 사실이 문장을 뒷받침하는지*는 사람이 확인한다. 사고를 인지한 시점, 피해, 신고자 정보와 동의·확인란은 사람이 채우도록 비워 둔다.

**왜 같은 요청에서 파일을 반환하는가.** 11월 19일 실제 생성 경로로 시험한 9건은 모두 유효한 초안을 반환했다(중앙값 22.8초, 최대 30.5초). 가장 긴 요청도 CloudFront가 서버 응답을 기다리는 60초 안에 끝나, 사용자가 별도로 결과를 조회할 필요가 없는 동기 응답을 유지했다. 모델 선정 실험에서 `gpt-6-luna`의 `high` 설정으로 성공한 호출은 최장 37.7초였다. 이를 근거로 모델 응답을 읽는 대기 시간은 기본 45초(설정 상한 50초)로 정했다. 연결·전송·사용 가능한 연결을 기다리는 시간은 각각 3초이며, 한 요청에서는 한 번만 시도한다.

**켜기와 실패 응답.** `REPORT_DRAFT_OPENAI_MODEL=gpt-6-luna`로 켜며 전용 reasoning effort의 기본값은 `high`다. 전용 모델 설정이 비어 있는 기본 상태나 제공자 자격증명이 없는 상태에서는 호출 없이 503 `REPORT_DRAFT_MODEL_UNAVAILABLE`을 반환한다. 시간 초과·제공자 사용 불가도 같은 503이고, 출력 형식이나 인용이 계약에 어긋나면 502 `REPORT_DRAFT_GENERATION_FAILED`다. 성공한 초안만 저장한다.

## Consequences (결과·트레이드오프)

- **분석 모델을 바꾸면 세 작업에 함께 적용된다.** 분석을 시작하는 디스패처가 모델 호출에 쓸 클라이언트 하나를 만들어 세 작업에 전달한다. 모델 이름(`OPENAI_MODEL`)과 추론 수준(`OPENAI_REASONING_EFFORT`)을 한 곳에서 관리하는 대신, 이 설정만으로 한 작업의 모델만 바꿀 수는 없다.
- **초안 파일을 받았다는 사실과 서술 품질은 별개다.** 270회 품질 측정 뒤 PR #669가 모델에 보내는 입력에 알림 발송 사실과 GuardDuty 활동 사실을 더했다. 변경 뒤인 11월 20일 실제 생성 경로로 시험한 9건은 모두 정해진 형식과 인용 검사를 통과했다(중앙값 21.3초, 최대 24.6초). 이는 새 입력으로 파일을 생성할 수 있다는 확인이다. 새 입력에서 같은 서술 품질이 나오는지는 다시 측정하지 않았다.
- **저장소 기본값과 운영 배포는 별개다.** PR #672로 코드와 `.env.example`에 분석 모델 `gpt-6-luna` low와 기본 꺼짐인 신고 초안 연결이 반영됐다. 해당 이미지의 운영 배포, 세 분석 경로의 실제 모델 호출, 신고 초안의 운영 활성화와 호출은 #648에서 미확인이다.
