## 이 문서를 읽는 법

설계서와 **나누는 이유는 수명이 다르기 때문**이다.

| | 설계서 `E2E_DEMO_SCENARIOS.md` | **이 문서** |
| --- | --- | --- |
| 묻는 것 | **무엇을** 시연하는가 — 트랙 구성·입력 선택 근거·계약 | **9/11에 무엇이 실제로 돌고, 무엇을 슬라이드로 넘기는가** |
| 수명 | 시연 설계가 바뀔 때까지 | **리허설 1차까지.** 끝나면 판정서만 남는다 |
| 낡는 방식 | 계약이 바뀌면 낡는다 | **코드가 하루만 움직여도 낡는다** |

그래서 이 문서의 모든 판정에는 **파일:줄 근거**를 붙인다. 옮겨 적은 값은 다시 재야 하고, 재는 방법이 적혀 있지 않으면 아무도 재지 않는다.

**용어** — *실경로*: 리허설에서 실제 코드가 돌아 화면·상태가 바뀌는 컷. *대체 컷*: 그게 안 되어 슬라이드·정적 이미지·미리 저장한 텍스트로 넘기는 컷. *수동 우회*: 프로덕션 배선은 없지만 스크립트·API 호출로 같은 상태를 만들어 그 뒤를 실경로로 잇는 것.

```bash

```

→ `db`·`localstack` 두 서비스가 `running`.

### 3-2. 2번이 「수동 우회」인 이유 — 본문이 있는 것과 경로가 서는 것은 다르다

```text
services/scheduler.py:32  run_pipeline()   수집 → 정형화 → 적재 → 판정      ← 여기서 끝난다
        ✗ 배선 없음  (IncidentIntake( 생성이 tests/ 밖에 0건)
incident_intake.py:215    create_incident_from_intake()                     ← 테스트만 부른다
        ↓ 자동
agent_dispatcher.py:407   dispatch_pending_analysis()   main.py:74 lifespan 배선 확인
```

PR #286(#265)으로 함수 본문은 dev에 들어왔다. **그러나 판정 결과를 `IncidentIntake`로 만들어 넘기는 코드가 프로덕션에 없다** — 라우터·`workflows.py`·`main.py`·`services/scheduler.py` 어디에도 없다.

**리허설 대응**: Incident를 수동으로 1건 만든다. 그 순간부터 3번 이후는 자동으로 흐른다.
**게이트 판정에는 별개다**: 5주차 판정 기준 ⓒ가 *"mock 없이 1건 관통"* 이라, 수동 호출을 충족으로 볼지는 PM 판단이다.

| # | 대체 방법 | 준비물 | 담당 |
| --- | --- | --- | --- |
| 7 | 슬라이드 1장 — `get_waiter` 2/2 판정 3분기(`OK`·`FAILED`·`TIMED_OUT`) 도식 | `services/aws/rollback.py`의 `StatusCheckVerdict`에서 그린다 | 박지현 |
