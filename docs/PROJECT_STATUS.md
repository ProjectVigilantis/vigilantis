- **관제**: AWS 단일 계정 / 1–2개 리전. **EC2·SG 중심** + 런북 조치 대상 리소스(NACL, EBS, ASG·Launch Template, ALB Target Group).

- **Golden Dataset 현재값**(2026-09-14 실측 · 이슈 #310): **하나의 숫자로 적을 수 없다 — 답이 셋이고 뜻이 다르다.** ① **입력 자산 32건** — 골든이 DB에 적재하는 자산(`datasets/golden/finops/input/`, 유형 7/7종) ② **판정 정답 28건** — 규칙 엔진 판정의 정답이 있는 자산. `scripts/load_golden_assets.py --verify`가 대조하는 수이며, 차이 4건은 **그래프 노드로만 쓰이고 판정 대상이 아닌** 토폴로지 전용 유형(NACL·Launch Template·ASG·ALB Target Group 각 1건)이다 ③ **SecOps 이벤트 16건** — 입력 16 / 정답 16. **⚠️ ②의 28과, 이 문서가 4주차까지 적어 온 `28건`은 숫자만 같고 뜻이 전혀 다르다**(후자는 자산+이벤트 합계였고 그나마 틀린 값이었다). §현재 위치의 4주차 기록에 있는 건수는 **그 시점의 값**이며 현재값으로 덮지 않는다.
- **AI**: OpenAI `gpt-5.6-luna`(`reasoning_effort=low`) + Pydantic v2 Structured Output + **LangGraph 오케스트레이션**. CoT 3줄 요약 + Runbook ID 추천. LangGraph는 프로젝트 정체성으로 MVP 구현 확정(2026-08-13) — 출력 계약(Pydantic 스키마)은 동일하게 유지.
- **조치별 절감 예상**(2026-09-07 확정 · **2026-09-17 산출 방식 개정** — 아래 결정 로그): 자산 인스턴스 수정 추천을 실행할 때 **얼마를 아낄 수 있는지**를 관제자가 확인할 수 있게 한다. **AI는 현재·목표 인스턴스 타입의 단가만 추정하고, 월 절감액·적용 조건·설명 문장은 서버가 만든다** — 가드레일을 통과한 `RIGHTSIZING` 후보에 대해 단가를 **별도로** 요청하는 방식이며, 종전의 *"금액과 근거를 모두 AI가 추천 호출에 실어 받는다"* 에서 바뀌었다. 단가표를 사람이 들고 유지하거나 Cost Explorer·Price List API를 붙이지 않는 것은 그대로다. 근거는 구조화 필드로 **저장해 두고 필요할 때 그 저장분을 쓴다** — 조회에서 다시 추정하지 않는다. 계약·실험 요약의 원문은 [`apps/core-api/ai/SAVINGS_V1.md`](../apps/core-api/ai/SAVINGS_V1.md)다. **비용 추이 그래프·누적 절감 캘큘레이터(집계·추이 축)는 범위 밖**이며, 이 결정은 개별 추천의 절감 예상 하나에 한한다.
- **4단계 가드레일(순서 고정)**: ① Schema Check ➔ ② Action Whitelist ➔ ③ ARN Match ➔ ④ AWS Dry-Run.
- **레콘(Reckon) — Incident 상태 축의 이름**(2026-09-03 확정, 아래 결정 로그): 가드레일(*실행해도 되는가*) 다음의 두 물음 — *실제로 무엇이 일어났는가* → *그 결과를 어떻게 수습·종료하는가* — 를 다루는 **Incident 상태와 그 상태를 관리하는 일련의 과정**을 부르는 고유명사. '가드레일'과 같은 층위로 쓴다.
- **양방향 회복**: 자산 = 스펙 JSON 백업 ➔ `get_waiter` Status Check(2/2) ➔ 자동 원복 / 보안 = 선제 차단 ➔ 관제자 [원클릭 해제].
- **3단계 위험 대응**: High `PRE_MITIGATION_0_5S`(0.5초 선차단 시뮬레이션) / Medium·Low `AGENT_WAIT`(승인 대기) / **Medium 1분 미응답 `TIMEOUT_ISOLATION_1M`(자동 격리) — Low는 제외**(2026-08-25 확정, 아래 결정 로그). **화면 표기**: Medium 대기 화면에 초 단위 카운트다운을 두지 않고 `제안 생성 시간`·`실행 예정 시간` **절대 시각 2종**만 보여준다(2026-08-27 확정, 아래 결정 로그).
- **FE**: Next.js 16 + Shadcn UI, 위협 토폴로지 맵(붉은색 노드), One-Click + Idempotency Key. **mock 계층은 없다**(2026-09-16 폐기, 아래 결정 로그) — 화면은 실 `core-api`에 직접 붙으므로 **백엔드가 떠 있어야 `apps/web`이 선다.**
- **아키텍처**: 단일 FastAPI 백엔드(`apps/core-api`) + PostgreSQL + APScheduler.
- **이번 범위 밖(추후 필요 — 2026-09-03 회의)**: 근거 조회 · **독립 시계열 분석 화면** · 시간 슬라이드 차트. 현 마일스톤 카드에 넣지 않는다. <br>※ **대시보드 추이 2축(EC2 CPU · 네트워크 In/Out)과 자산 상세 스파크라인은 구현됐다**(2026-09-21 · #294 / PR #387 · `GET /api/v1/metrics/timeseries`). 2026-09-03 회의가 범위 밖으로 민 것은 **따로 선 시계열 분석 화면과 시간 축을 사람이 끌어 보는 슬라이드 차트**이고, 위 둘은 대시보드·자산 패널 안의 추이 띠라 그 축이 아니다 — **회의 결정을 뒤집은 것이 아니므로 §확정 결정 로그에 행을 더하지 않는다**(2026-09-22 PM 판단).

## API 계약 (확정 — FE↔BE 공개 계약, 코드 원천: `packages/schemas/api/`)

- `GET /api/v1/assets` — EC2/SG 상태·스펙·연결관계·헬스 스코어(**0–100 정수**)·Skip 사유 코드(`SkipReasonCode` **6종** — `SKIP_UNSUPPORTED_STATE`는 EBS가 `available`·`in-use` 외 전이·비정상·미상 상태일 때의 **판정 보류**이며 2026-09-03 #276 / PR #284로 추가됐다) 봉투에 `uncollected`(이번 회차에 **조회 자체를 못 한** 자산 유형 목록 — 항목은 `{asset_type, reason_code}`)를 함께 싣는다. `items`의 유형별 0건만으로는 *"그런 자원이 없다"* 와 *"못 가져왔다"* 가 구분되지 않아 **화면이 후자를 정상으로 그리던 자리**를 닫는다 — LocalStack Community에 `elbv2`·`autoscaling`이 없어 대상 그룹·Auto Scaling 그룹 수집이 매 회차 degrade되는 것이 그 자리였다([ADR-0006](adr/0006-localstack-team-standard-env.md) §4). `asset_type`은 **화면이 가진 축**이라 수집기 라벨이 아니라 자산 유형으로 내린다. `reason_code`는 AWS 오류 코드(`InternalFailure`·`AccessDenied`·`Throttling` 등) 또는 예외 클래스명이며 **자유 문자열이다** — AWS가 코드를 늘릴 때마다 계약을 고치지 않으려고 enum으로 닫지 않았다. **비어 있다고 전부 성공했다는 뜻은 아니다** — 서버가 원인을 자산 유형으로 환원하지 못하면 지어내지 않고 비워 둔다. 불변식 3종: 값이 있으면 `collection_status`는 `PARTIAL`·`FAILED`만 허용(`READY`면 화면이 *"정상"* 이라고 말하게 된다) · `asset_type` 중복 금지(리전이 여럿이면 같은 유형이 여러 번 실패하므로 **접는 책임은 서버**다) · `NOT_COLLECTED`면 비어 있어야 한다(아무것도 시도하지 않은 상태다) (2026-09-21, #294 / PR #387)
- `GET /api/v1/incidents` — 목록(상세의 부분집합 10필드 + nullable `title`). `status`·`category` 필터, `created_at` 내림차순 전체 반환(페이지네이션 Post-MVP)
- `GET /api/v1/incidents/{id}` — nullable `title`, AI CoT 3줄 요약, Evidence ID, 추천 Runbook(본편 7종만)·실행 요약(관제자 복구 조치는 롤백 3종만). 추천 항목의 `display_parameters`는 **화면 표시 전용**이며 **서버가 typed `parameters`에서 파생**한다 — LLM이 짓지 않고, 실행 요청(`POST /actions/execute`)에 되돌려 받지도 않는다(2026-08-27, #154 / PR #178) 실행 요약의 `verification_hold`는 **판정 불가 보류 기록**(사유 코드·횟수·처음/마지막 실패 시각)이며 없으면 null이다 — `UNVERIFIED`면 반드시 있고 `SUCCESS`·`ROLLBACK_INITIATED`에는 오지 않는다(2026-09-14, #249 / PR #341) 추천 항목의 `ai_savings_estimate`는 **조치별 절감 예상**이며 상태로 갈린다 — `ESTIMATED`는 금액과 근거를 싣고, `UNAVAILABLE`·`INVALID`는 **사유만 싣고 금액·근거를 null로 둔다.** 기존·비대상 후보는 **필드 전체가 null이다.** 단가 출처는 `MODEL_KNOWLEDGE`(모델 추정), 설명 출처는 `SERVER_TEMPLATE`(서버 생성)으로 표기해 **AI 추정값과 서버 파생 사실값을 계약에서 가른다.** 조회에서 재추정하지 않는다 (2026-09-17, #347 / PR #361 · 산출 방식은 §확정 결정 로그 2026-09-17)
- `GET /api/v1/metrics/timeseries` — 대시보드 추이 차트의 원천. **3축을 한 응답에 싣고 축마다 상태를 따로 매긴다**: ① EC2 CPU 사용률(CloudWatch 원계열) ② 네트워크 In/Out(한 자산 안에 짝으로) ③ 인터넷 개방 보안 그룹 건수(회차별 이력). **한 축이 실패해도 다른 축은 값을 준다** — 축별 `status`(`AxisStatus` — **축 하나의 조회 결과** 상태값. 이 값이 없으면 한 축의 실패가 나머지 두 축까지 빈 차트로 만든다)가 그 자리를 담당하며 봉투 전체를 실패로 접지 않는다. 네트워크 축은 `period`(한 데이터 점이 덮는 **집계 구간(초)**)당 **바이트 원값**을 그대로 주고 초당 환산은 화면 몫이다 — 서버는 관측값을 가공하지 않는다(수집 경로가 쓰는 `Average`와 통계를 나눴다 — period 안에 표본이 여럿이면 평균은 표본 하나치가 되어 초당 환산이 표본 수만큼 작아진다). 불변식 2종: **축의 상태와 값은 같이 간다**(실패 축의 계열은 비고 준비 축은 계열이 있다 — 화면이 *"상태는 정상인데 값이 없음"* 을 만나지 않는다) · **네트워크 In/Out은 한 자산 안에서 짝이다**(두 계열을 화면이 다시 맞추는 책임을 지지 않는다). CPU와 네트워크는 CloudWatch 호출을 나눈다 — 네트워크만 인스턴스당 쿼리가 2개 더 붙어 한도·권한에 먼저 걸리므로, 같이 부르면 CPU 곡선까지 함께 사라진다 (2026-09-21, #294 / PR #387)
- `POST /api/v1/incidents/{id}/resolve` — 관제자의 **종료 판단 기록**. 상태 전이·트랜잭션은 서버(`workflows.resolve_incident`)가 소유하고 라우터는 받아 넘긴다. 지금 종료할 수 없는 인시던트는 `INCIDENT_NOT_RESOLVABLE`(409)로 거절한다. **추가 조치 없이 닫는 경로를 포함한다** — SecOps 분석이 제안 없이 끝난 경우가 그 자리다(#381 / PR #386). (2026-09-04 #199 신설 · 2026-09-21 사용자 종료 보강. **§API 계약 등재가 빠져 있던 것을 2026-09-22 갱신에서 채웠다** — `README.md`가 PR #384로 먼저 행을 넣어 **소개용 문서가 공개 계약의 단일 기준보다 앞서 있었다.**)
- `POST /api/v1/actions/execute`
  - Request: `{ incident_id, runbook_id, idempotency_key }` — 추가 필드 거부, Target ARN·AWS 파라미터는 받지 않음
  - HTTP: 신규 접수 **`202 Accepted`**, 같은 `idempotency_key` 재요청 **`200 OK`**(멱등 재생 — 본문은 두 경우가 같다)
  - Response status: `IN_PROGRESS | SUCCESS | FAILED | ROLLBACK_INITIATED | ROLLED_BACK | ROLLBACK_FAILED | UNVERIFIED` — `ROLLED_BACK`·`ROLLBACK_FAILED` = 복구 최종 결과, `UNVERIFIED` = **결과 확인 불가**(AWS 조회 실패로 판정 재시도를 소진해 자동 판정을 멈춘 종료 상태 — 자동 원복하지 않고 관제자 원복을 연다). 셋 다 원본 Execution에만 기록
- WebSocket `/api/v1/ws` — `INCIDENT_CREATED | INCIDENT_UPDATED | EXECUTION_UPDATED` 이벤트 봉투 (DB commit 이후 전송, 상태 원본 아님)
- REST 공통 오류 봉투 `{"error": {code, message, request_id}}` — 코드 **6종**: `INCIDENT_NOT_FOUND`(404) · `IDEMPOTENCY_KEY_CONFLICT`(409 — 같은 멱등 키로 다른 요청이 온 경우) · `PROPOSAL_NOT_EXECUTABLE`(409 — 그 추천이 실행 가능한 상태가 아님) · `INCIDENT_NOT_RESOLVABLE`(409 — 그 인시던트를 지금 종료할 수 없음) · `REQUEST_VALIDATION_FAILED`(422) · `INTERNAL_ERROR`(500). 코드 원천은 `packages/schemas/api/errors.py`의 `ErrorCode`다. **종전 표기 "코드 5종(404·409×2·422·500)"은 실제와 달랐다** — 409가 둘이 아니라 셋이며, 셋째(`INCIDENT_NOT_RESOLVABLE`)가 위 `resolve` API와 함께 들어왔다(2026-09-22 갱신에서 정정)
