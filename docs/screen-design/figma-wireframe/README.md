# Vigilantis 와이어프레임 생성기 (Figma 플러그인)

`screen-design-v1.2.md` 4장의 화면을 피그마 프레임 16개로 생성한다.
저충실도 · 회색조 전용이며, **색으로 의미를 전달하지 않는다.**

## 실행 방법

Figma **데스크톱 앱**이 필요하다. 웹 버전(figma.com)은 로컬 매니페스트를 못 읽어
플러그인 개발 모드가 되지 않는다.

1. [Figma 데스크톱 앱](https://www.figma.com/downloads/) 설치 후 로그인
2. 아무 디자인 파일이나 열기
3. 메뉴 → `Plugins` → `Development` → `Import plugin from manifest…`
4. 이 폴더의 `manifest.json` 선택
5. `Plugins` → `Development` → **Vigilantis 와이어프레임 생성기** 실행

현재 페이지에 12개 프레임이 3열로 생성되고, 뷰포트가 그쪽으로 이동한다.
이미 있는 요소는 건드리지 않는다. 결과가 마음에 안 들면 생성된 것만 지우고 다시 돌리면 된다.

## 프로토타입

프레임을 만든 뒤 클릭 인터랙션(`ON_CLICK` → `NAVIGATE`)까지 자동으로 연결한다.
설계서 2장의 흐름도를 그대로 옮긴 것이다. 우측 패널 `프로토타입` 탭에서 확인하고,
▶ 버튼으로 바로 클릭해 볼 수 있다.

**시작점 2개**

```
흐름 A — 자산 최적화              :  DSH-001 에서 시작
흐름 B — 보안 위협 (Toast 수신)   :  CMN-001 에서 시작
```

**주요 경로**

```
A:  DSH-001 → AST-001 목록 → AST-002 드로어 → INC-002 A
                                   → ACT-001 A 실행 → ACT-002 실행 상태

B:  CMN-001 Toast [상세 보기] → INC-002 B
                    → ACT-001 B 해제 → ACT-002 실행 상태
```

## 사전 점검

피그마 없이 플러그인을 돌려보는 스텁 하네스가 있다.

```bash
node check.js                          # 이 맥 기준 (한글 로컬라이즈 폰트명)
FONT_SCENARIO=english node check.js    # 영문 폰트명 환경
FONT_SCENARIO=interOnly node check.js  # 한글 폰트가 없는 환경
```

**잡는 것** — 오타 난 헬퍼, `characters`보다 늦게 지정한 `fontName`(피그마에서 즉시
예외), NaN·0 크기, 프레임 겹침, 실행 중 예외, 그리고 **오토레이아웃 접힘**.

접힘 검사가 제일 중요하다. `layoutGrow = 1`은 "남는 공간을 나눠 갖는다"는 뜻이라
부모의 주축이 AUTO(hug)면 남는 공간이 0이고 자식이 0으로 접힌다. 첫 실행에서
이것 때문에 첫 실행에서 프레임이 전부 GNB 바만 남고 사라졌다. 그래서 규칙 자체를 검사한다.

- 가로 `row` 안의 카드는 `stretch: true`가 있어야 높이가 채워진다
- 화면 프레임은 높이를 고정한다(`SCREEN_H`). hug로 두면 안쪽 `grow`가 전부 죽는다

**넘침 검사**도 함께 돈다. 높이를 고정한 프레임에 내용이 넘치면 Figma가 조용히 잘라내므로,
`_h`를 잠시 비워 내용 기반 자연 높이를 재서 비교한다. `stretch`·`grow`로 부모가 크기를
정하는 축은 제외한다(그 축을 재면 전부 오탐이 된다).

프레임 크기는 **1920 × 1080 (16:9)** 이다. 발표·모니터가 전부 16:9라 레터박스 없이 꽉 찬다. 타깃 브라우저 뷰포트
기준이며 보는 사람 모니터에 맞추지 않는다. 화면보다 크면 Figma가 줌으로 맞춘다.

프로토타입도 함께 검사한다 — 모든 링크가 **최상위 프레임**을 가리키는지(중간 노드를
가리키면 죽은 링크가 된다), 플로우 시작점의 `nodeId`가 비어 있지 않은지(키 오타),
도착 링크가 없는 화면이 없는지.

**못 잡는 것** — 실제 렌더 모양, 한글 폰트 폴백, 오토레이아웃 미세 동작.
이건 피그마에서 한 번 돌려봐야 확인된다.

## 폰트

`FONT_PREFERENCE` 순서로 설치된 폰트를 찾는다.

```
Pretendard → Noto Sans KR → Apple SD Gothic Neo → Spoqa → Inter → Roboto
```

**macOS는 폰트 이름을 한글로 로컬라이즈해서 내준다.** 이 맥의 Apple SD Gothic Neo는
패밀리가 `Apple SD 산돌고딕 Neo`, 스타일이 `일반체`·`볼드체`로 잡힌다. 영문 이름만
비교하면 매칭에 실패해 본문이 통째로 얇은체나 볼드로 나온다. 그래서 패밀리·스타일 모두
정규식으로 받고, 한글·영문 이름을 둘 다 인식한다.

한글이 네모(두부)로 보이면 한글 폰트가 하나도 없는 것이다. Pretendard나
Noto Sans KR을 설치하고 다시 실행하면 된다.

## 화면을 고치려면

`code.js`의 `screens()` 안에서 해당 화면만 고친다. 스펙 DSL을 쓴다.

```js
col({ gap: 12, pad: 14 }, [ ... ])   // 세로 오토레이아웃
row({ gap: 8, align: "CENTER" }, [ ... ])  // 가로 오토레이아웃
txt("라벨", { size: 12, bold: true })
box({ w: 120, h: 40, label: "플레이스홀더" })
gap()     // 남는 공간 밀어내기 (layoutGrow = 1)
rule()    // 1px 구분선
```

`grow: 1`은 주축을 채우고, `stretch: true`는 교차축을 늘린다.
고친 뒤 `node check.js`로 먼저 확인하고 피그마에서 다시 실행한다.

## 알아둘 것

화면 구조의 기준은 **화면설계서**다. 이 플러그인은 그걸 그리기만 한다.
레이아웃을 바꿔야 하면 설계서를 먼저 고치고 여기에 반영한다. 반대로 하면
문서·와이어프레임·구현이 갈라진다.

와이어프레임은 실행 중인 구현(`apps/web`)에서 나온 스냅샷이다. 계약이 바뀌면
자동으로 따라오지 않는다.
