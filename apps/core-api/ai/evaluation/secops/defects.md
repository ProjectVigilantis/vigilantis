# SecOps 품질 개선 근거

합성 SSH 사례(C01–C07, #583 2단계에서 합성 선행 격리 기록을 더한 C08·C09, 3단계에서 무제안만 정답인 C10)에서 발견한 결함과 프롬프트·평가 기준의 변경 이유를 정리한다. 각 회차의 규모·당시 판정은 [실험 요약](results/README.md), 현재 허용 결과와 재검증 절차는 [품질 기준](baseline.md)이 원천이다.

## 서비스 역할과 평가 기준

관제자는 분석 근거와 조치 선택지를 읽고 승인 또는 거절·종료를 판단한다. 후보 생성, 가드레일 수용, 승인, 실행, 실제 효과와 종료는 서로 다른 사실이다. LOW 또는 후보 부재만으로 위험이 없다고 하거나 자동 종료를 결정하지 않는다.

v0.5.2까지 C01–C05는 후보 필수, C06–C07은 무제안 필수로 평가했다. 5차 이후에는 후보를 제시하면서 현재 적용을 보류할 수도 있다는 점을 반영해, v0.5.3부터 일곱 사례 모두 근거 있는 후보·무제안을 허용했다. C08·C09도 같은 허용이며, 3단계의 C10만 무제안만 허용한다(아래 22차 행). 후보 수 자체를 위험 강도나 조치 이유의 정답으로 삼지 않는다. 같은 관측·진단은 후보 유무에 따라 반드시 달라질 필요가 없지만 실제 후보·값과 요약이 모순되면 실패다.

5차의 원래 19 PASS / 2 FAIL과 새 의미 기준에 따른 21 PASS 재분류는 다른 판정이다. 기존 무제안 지시와의 불일치는 당시 결함으로 남고, 재분류는 새 모델 출력의 개선 증거가 아니다.

## 평가 도구의 책임

- CI는 동결 fixture로 평가 입력을 검증한다. 타 담당 Golden·corpus 파일의 변경 여부는 계측 CLI가 실행 시점에 검사한다.
- 요청 호환성은 프롬프트·전달 JSON·응답 스키마와 서비스 설정으로 판단한다. 파일 전문 지문은 별도 진단값이며, 무관한 주석·FinOps 변경만으로 유료 재측정을 요구하지 않는다.
- SecOps 프롬프트 지문을 CI에 고정하고, 결정적 내부 식별자 검사와 인용에 근거한 의미 검토를 구분한다.
- 사례별 비율의 산술 충족(`case_acceptance.threshold_met`), 관측 완전성(`measurement.fully_observed`), 기준선 후보 여부(`case_acceptance.baseline_candidate`)를 따로 낸다. 입력 보강 같은 수정의 구현은 품질 개선의 증거가 아니며, 결함은 새 측정으로 확인할 때까지 미해결로 둔다. 비율 기준 충족도 전원 PASS나 결함 소멸이 아니므로 남은 FAIL을 함께 기록한다.
- 기준·출력을 바꾼 시점과 당시 판정을 보존한다. 프롬프트 수정, 오프라인 재분류, 새 출력 측정은 각각 별도의 근거다.
