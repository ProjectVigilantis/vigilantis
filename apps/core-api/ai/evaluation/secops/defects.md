# SecOps 품질 개선 근거

합성 SSH 7사례에서 발견한 결함과 프롬프트·평가 기준의 변경 이유를 정리한다. 각 회차의 규모·당시 판정은 [실험 요약](results/README.md), 현재 허용 결과와 재검증 절차는 [품질 기준](baseline.md)이 원천이다.

## 서비스 역할과 평가 기준

관제자는 분석 근거와 조치 선택지를 읽고 승인 또는 거절·종료를 판단한다. 후보 생성, 가드레일 수용, 승인, 실행, 실제 효과와 종료는 서로 다른 사실이다. LOW 또는 후보 부재만으로 위험이 없다고 하거나 자동 종료를 결정하지 않는다.

v0.5.2까지 C01–C05는 후보 필수, C06–C07은 무제안 필수로 평가했다. 5차 이후에는 후보를 제시하면서 현재 적용을 보류할 수도 있다는 점을 반영해, v0.5.3부터 일곱 사례 모두 근거 있는 후보·무제안을 허용했다. 후보 수 자체를 위험 강도나 조치 이유의 정답으로 삼지 않는다. 같은 관측·진단은 후보 유무에 따라 반드시 달라질 필요가 없지만 실제 후보·값과 요약이 모순되면 실패다.

5차의 원래 19 PASS / 2 FAIL과 새 의미 기준에 따른 21 PASS 재분류는 다른 판정이다. 기존 무제안 지시와의 불일치는 당시 결함으로 남고, 재분류는 새 모델 출력의 개선 증거가 아니다.

## 프롬프트와 그래프 보완

| 발견한 문제 | 반영한 변경 | 확인 결과·한계 |
| --- | --- | --- |
| 요약이 실제 재평가·후보를 알지 못함 | 위험 재평가 → 후보 생성·계약 검증 → 요약 순서를 유지하고 실제 결과를 요약에 전달 | 그래프 전체 재설계 대신 필요한 선행 결과를 명확히 했다. 저장·화면·종료 통합과는 별도다. |
| 위험 등급·시각·발췌 해석의 오류 | v0.5.0–v0.5.2에서 전체 창·횟수·빈도, 관측 시각·자산 보존 시각, 집계·발췌를 구분 | 부분 비교에서 개선했지만 4차의 성긴 반복·단발 표현은 판정 보류로 남았다. 단발/반복의 관측 단위를 추가로 명시했다. |
| 후보·기록 부재를 사실 부재로 확대함 | 무제안 이유를 관측에 연결하고, 선행 실행 기록 부재는 실행 여부 미확인으로 설명 | 3차 부분 비교에서 앞선 실패가 관측되지 않았다. 선행 실행이 있는 입력의 모델 품질은 미측정이다. |
| 후보 수를 강제해 사용자 판단과 충돌함 | v0.5.3에서 프롬프트·답지·rubric을 후보·무제안 허용으로 정렬 | 선택지 존재와 현재 적용 판단을 분리했다. 무제안 이유의 타당성도 계속 평가한다. |
| NACL의 실제 영향 경계가 빠짐 | v0.5.4에서 출발지 한 주소 → 연결 서브넷으로 유입 → TCP 전체 포트를 먼저 설명 | 6차의 범위 누락 3건을 보완해 7차에서 당시 기준 21건이 통과했다. 규칙 가용성·우선순위·효과는 별도 확인 사항이다. |
| 초기 등급 복사에 치우친 재평가 | v0.5.5에서 초기값 앵커 문장을 빼고 서버 위험 판정 상수를 프롬프트에 주입 | 관측 횟수·빈도로 이유를 설명하게 했다. 초기 위험도는 별도로 보존하고 임계값의 중복 관리를 피한다. |
| 내부 필드명과 enum 원문이 관제자 요약에 노출됨 | v0.5.5에 결정적 노출 검사를 추가하고 관제자 표현을 요구 | 새 검사로 7차 출력 21건이 실패했다. 8차에는 노출 3건과 등급 모순 1건이 남았다. |
| 내부 필드명이 예문에 남고 재평가와 요약이 모순됨 | v0.5.6에서 예문을 관제자 표현으로 바꾸고 실제 재평가 등급의 한국어 표기를 요약 입력에 함께 전달 | 입력·답지·rubric·위험/후보 프롬프트는 8차와 유지했다. 9차는 21건 통과했으며 약한 표현과 미측정 범위는 결과에 남겼다. |

## 평가 도구의 책임

- CI는 동결 fixture로 평가 입력을 검증한다. 타 담당 Golden·corpus 파일의 변경 여부는 계측 CLI가 실행 시점에 검사한다.
- 요청 호환성은 프롬프트·전달 JSON·응답 스키마와 서비스 설정으로 판단한다. 파일 전문 지문은 별도 진단값이며, 무관한 주석·FinOps 변경만으로 유료 재측정을 요구하지 않는다.
- SecOps 프롬프트 지문을 CI에 고정하고, 결정적 내부 식별자 검사와 인용에 근거한 의미 검토를 구분한다.
- 기준·출력을 바꾼 시점과 당시 판정을 보존한다. 프롬프트 수정, 오프라인 재분류, 새 출력 측정은 각각 별도의 근거다.
