# SecOps 후보 재측정 계획 — v1.0.1 (NACL 규칙 번호)

후보 프롬프트 **v1.0.1**의 품질 재측정 계획이다. 상태는 측정 대기(`PENDING`)이며 측정 결과나 품질 승인을 담지 않는다. 공개 기준선 **v1.0.0**과 1–9차 결과는 바꾸지 않는다([품질 기준](../baseline.md), [실험 요약](../results/README.md)).

## 변경 내용

- NACL 규칙 번호 충돌을 막기 위해 `rule_number`를 서버가 계산한다. Dispatcher가 모델 호출 전에 대상 NACL의 inbound 규칙과 동일 NACL의 승인 대기·미종료 실행 후보가 사용하는 번호를 제외하고 가장 작은 번호를 고른다. 범위는 1~32766 중 첫 inbound allow 규칙의 번호보다 작은 번호이며, allow가 없으면 유효 범위 전체다. 계산한 매핑은 그래프에 주입한다. DB 조회 결과는 번호 예약이 아니며, 동시 선택의 충돌은 실행 직전 검증으로 거절한다.
- 모델은 대상·`cidr_block`·`protocol`만 고르고, 프롬프트는 `rule_number`를 `null`로 두도록 지시한다.
- 빈 번호가 없거나 조회에 실패하면 기존 `FAILED` 경로로 처리하고 대체 후보를 만들지 않는다.
- 프롬프트가 바뀌므로 [품질 기준](../baseline.md)의 "SecOps 프롬프트·전달 JSON·응답 스키마·모델 설정 변경" 행에 따라 후보 지문을 고정하고 이 계획을 기록한다. 지문 고정만으로 품질을 승인하지 않는다.

## 유지되는 기준

- [answers.json](../answers.json)·[rubric.json](../rubric.json)·채점 기준은 바꾸지 않는다. `rule_number`의 1~32766 범위 검사도 그대로이며, v1.0.1에서 검사 대상은 서버가 계산한 값이다.
- 합격선은 [품질 기준](../baseline.md)과 같다. C01~C07 × 3회의 구조화 21건·의미 항목 168개·식별자 검사 21건이 모두 PASS여야 한다. 누락·오류·UNSURE를 분모에서 빼지 않는다.

## 범위 구분

| 범위 | 근거 | 현재 상태 |
| --- | --- | --- |
| 공개 기준선 v1.0.0 | v0.5.6 9차 측정과 최종 기능 회귀 | 유지. `approved`와 기존 결과는 변경하지 않음 |
| 코드 회귀 | 변경 PR의 테스트·CI | PR·CI에 기록. 품질 측정으로 세지 않음 |
| 후보 v1.0.1 품질 | 아래 재측정 | 미실행(`PENDING`) |

오프라인 하네스의 규칙 번호 매핑은 결정적 테스트 대역이다. 이 매핑을 쓴 테스트·측정은 실제 AWS NACL 조회나 번호 선택의 근거가 아니다.

## 재측정 계획 (미실행)

- 규모: C01~C07 × 3회 = 그래프 21회. 정상 경로 호출 3회 기준으로 논리 모델 호출은 최대 63회다(전송 재시도 제외).
- 조건: 동결 입력·답지·rubric과 v1.0.1 후보 프롬프트. 모델 설정은 승인 요청 시점의 현재 서비스 설정을 쓴다.
- 사전 승인: 측정 라운드마다 실행 전에 열 수·호출 수·추정 비용·소요 시간·원자료 저장 경로를 보고하고 별도 승인을 받는다. 비용과 시간은 승인 요청 때 현재 서비스 설정으로 산정하며 이 문서에 미리 적지 않는다.
- 판정 점검: 정답지·채점·프롬프트 감사처럼 판단이 들어가는 점검을 하면 같은 브리프를 Claude Opus 5.5(effort high)와 GPT 6.1 sol(effort high)에 각각 주고 결과를 행 단위로 대조한다. 판단이 갈린 행만 사용자가 판정한다. 이 점검 호출은 위 63회에 포함되지 않으며, rubric의 판정 기준을 바꾸지 않는다.
- 결과 처리: 새 회차로 [실험 요약](../results/README.md)에 추가하고 기존 기록을 덮어쓰지 않는다. PASS면 최종 회귀와 공개판 확정을 거쳐 승인판으로 옮기고, FAIL이면 후보 상태를 `FAIL`로 바꾸고 결과 기록을 연결한다.

## 이 계획의 범위 밖

- 실제 NACL 배포·승인·실행·복구 측정은 머지 후 별도로 수행한다.
- 실제 공격 탐지율, 실제 AWS 실행과 통신 효과는 품질 측정이 보장하지 않는다.
