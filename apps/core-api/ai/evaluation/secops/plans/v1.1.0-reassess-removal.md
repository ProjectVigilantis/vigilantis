# SecOps 후보 재측정 계획 — v1.1.0 (위험 재평가 노드 제거)

후보 프롬프트 **v1.1.0**의 재측정 계획이다. 상태는 측정 대기(`PENDING`)이며 측정 결과나 품질 승인을 담지 않는다. 공개 기준선 **v1.0.0**과 1–9차 결과는 바꾸지 않는다([품질 기준](../baseline.md), [실험 요약](../results/README.md)). 측정 전이던 후보 v1.0.1([계획](v1.0.1-nacl-rule-number.md))은 이 후보로 대체됐고, 그 변경(서버가 NACL 규칙 번호를 정함)은 v1.1.0에 그대로 포함된다.

## 변경 내용 (ADR-0005 1차 개정 · #583 1단계)

- `reassess_risk` 노드와 그 프롬프트·응답 스키마(`RiskReassessmentOutput`)를 제거했다. 위험 등급은 서버 초기 판정(`initial_risk`) 하나이며 그래프는 등급을 다시 매기지 않는다.
- 출력 `reviewed_risk_level`은 null이다. 값이 실리면 Dispatcher가 `REVIEWED_RISK_MISMATCH`로 출력 전체를 FAILED로 바꾼다.
- 요약 프롬프트는 재평가 등급 대신 서버 초기 판정의 한국어 표기(`initial_risk_label`)를 설명 대상으로 받는다. 서버 임계값 문단은 프롬프트에서 빠졌고, 임계값을 지어내지 않도록 지시한다.
- 정상 경로 모델 호출은 후보 생성·요약 2회다. 그래프 순서는 후보 생성·검증 → 요약 → 출력 검증으로 그대로다 — 요약을 후보 앞에 두는 순서 복귀와 1회 호출은 #583 2단계다.

## 유지되는 기준

- [rubric.json](../rubric.json)과 의미 채점 기준은 바꾸지 않는다.
- [answers.json](../answers.json)은 `reviewed_risk_levels` 기대값을 뺐다. 구조화 채점은 그 대신 출력에 등급이 실리지 않았는지(`reviewed_risk_present`)를 본다. 후보의 대상·근거·CIDR·protocol·규칙 번호 범위 검사는 그대로다.
- 합격선은 [품질 기준](../baseline.md)과 같다. C01~C07 × 3회의 구조화 21건·의미 항목 168개·식별자 검사 21건이 모두 PASS여야 한다.

## 재측정 계획 (미실행)

- 시점: #583 3단계에서 별도 승인 후 수행한다. 2단계가 요약 스키마·순서를 다시 바꾸면 그 변경판이 이 후보를 대체하고, 측정은 대체된 후보로 한다.
- 규모: C01~C07 × 3회 = 그래프 21회. 정상 경로 호출 2회 기준으로 논리 모델 호출은 최대 42회다(전송 재시도 제외).
- 조건: 동결 입력·답지·rubric과 측정 시점의 후보 프롬프트. 모델 설정은 승인 요청 시점의 현재 서비스 설정을 쓴다.
- 사전 승인: 측정 라운드마다 실행 전에 열 수·호출 수·추정 비용·소요 시간·원자료 저장 경로를 보고하고 별도 승인을 받는다.
- 판정 점검: 정답지·채점·프롬프트 감사처럼 판단이 들어가는 점검은 같은 브리프를 Claude Opus 5.5(effort high)와 GPT 6.1 sol(effort high)에 각각 주고 결과를 행 단위로 대조한다. 판단이 갈린 행만 사용자가 판정한다.
- 결과 처리: 새 회차로 [실험 요약](../results/README.md)에 추가하고 기존 기록을 덮어쓰지 않는다. PASS면 최종 회귀와 공개판 확정을 거쳐 승인판으로 옮기고, FAIL이면 후보 상태를 `FAIL`로 바꾸고 결과 기록을 연결한다.

## 이 계획의 범위 밖

- `decision` 필드, 근거 선행 순서, SecOps 실행 계획의 코드 조립(#583 2단계)과 FinOps 재측정(3단계).
- 실제 공격 탐지율, 실제 AWS 실행과 통신 효과.
