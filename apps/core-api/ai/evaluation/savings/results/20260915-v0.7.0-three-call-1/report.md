`scored.json`의 `GRAPH_FAILED_OR_EMPTY` 1건은 가격 오차나 서버의 절감 계약 거부가 아니다. 요약 요청 단계의 외부 호출 실패다. `fact` 위반 목록이 빈 것도 요약이 정확했다는 뜻이 아니다. 실제 요약은 빈 배열이다.

관측 usage로 계산된 비용 필드는 `$0.00`이지만, usage를 받지 못했으므로 청구액 0달러를 확인한 결과로 쓰지 않는다. 정상 생성 응답·가격 채점 건수는 모두 0이다. 전체 품질 기준선은 `complete=false`, `passed=false`이며 이번 시도로 3호출 구성의 품질을 판단할 수 없다.

## 원인 확인

추가 유료 생성 없이 같은 설정으로 `GET /models/gpt-5.6-luna`를 1회 조회했다. 응답은 **HTTP 401 / `AuthenticationError` / `invalid_api_key`**였다.

- 실행기는 작업 worktree의 `.env`를 읽는 `Settings()`를 사용했다.
- 프로세스 환경변수의 `OPENAI_API_KEY` 덮어쓰기는 없었다.
- 기본 체크아웃과 worktree의 키 값은 서로 다르다. 값 자체는 출력·기록하지 않았다.
- worktree 설정으로 인증할 수 없다는 점은 확인했다. 첫 생성 요청은 SDK 세부 오류를 보존하지 않아 같은 401이었는지 직접 확인할 수 없지만, 같은 자격증명의 메타데이터 조회에서 인증 실패가 재현됐다.
- 이 시점에는 기본 체크아웃 키를 이용한 무료 유효성 조회가 자동 승인 검토에 거절돼 **미실행**이었다. 이후 사용자 승인과 성공한 조회는 아래 후속 실행 조건에 별도로 기록했다.

인증 문제와 프롬프트 품질 문제를 분리한다. 이번에는 모델이 답을 만들지 못해 v0.6.0에서 관찰했던 가격 오차·계약 거부 원인을 추가로 확인하지 못했다.

## 승인 검토 이력

1. 첫 실행 요청은 골든 입력·프롬프트의 외부 전송 승인이 부족하다는 이유로 자동 승인 검토가 차단했다. 이때 프로세스·네트워크 호출은 시작되지 않았다.
2. 실제 전송 자료의 범위를 오프라인으로 확인했다. 골든 문서는 더미 테스트 데이터로 명시하고, 입력 세트는 `mode=localstack`, 계정 `123456789012`다. 가격 요청의 입력 지문은 이전 v0.6.0과 일치했다.
3. 사용자가 외부 전송을 명시적으로 승인한 뒤 실행했다. 위 1회 실패는 자동 승인 차단과 별개로 실제 OpenAI 호출 경계에서 발생했다.
4. 기본 체크아웃의 다른 키로 인증을 확인하려는 요청은 별도 키 사용 승인이 없다는 이유로 다시 자동 승인 검토가 차단했다. 다른 경로로 우회하지 않았다.
