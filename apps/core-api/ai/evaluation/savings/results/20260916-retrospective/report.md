# #347 절감 예상 구현·실험 회고

작성: 2026-09-16. 대상: 이 작업에서 보존한 v0.3.0~v0.9.1 실험과 호출 순서 재검토.
이 문서는 과거 실행의 종합 기록이다. 새 모델 호출은 0회이며, 과거 결과·판정·승인 스냅샷을 변경하지 않는다.

## 1. 현재 결론

- **구현한 것:** 단가 추정 계약, 서버의 월 절감액 계산, 선택적인 후보 저장 필드, 상세 API 조회, 실패·기존 데이터 호환 처리. 현재 작업 코드는 v0.9.1의 그래프 내부 3호출이다.
- **아직 통과하지 못한 것:** 최종 단가 품질, 승인 요약 기준선 재통과, 새 호출 순서의 서비스 검증. v1.0.0·커밋·PR은 확정하지 않았다.
- **이번 대화의 방향 결정:** FinOps 후보를 생성하고 실행 가드레일을 통과시킨 뒤, 해당 RIGHTSIZING 후보에 절감 예상을 붙인다. 호출 위치 변경은 아직 구현하지 않았다.
- **유지할 역할:** 서버가 대상·목표 사양·과금 가정을 정하고 AI가 두 시간당 단가를 추정한다. 서버가 차액을 계산하며 FE는 저장본을 소비한다.
- **구분할 보장:** 가드레일 통과는 실행 명령 검사 결과이고, 서버 계산 성공은 산술 정합성이다. 둘 다 AI 단가가 실제 가격과 일치한다는 보장은 아니다.

## 3. 남겨야 할 핵심 사례

### 3.1 정확한 계산은 잘못된 단가를 고치지 않는다

산식은 `(현재 시간당 단가 − 목표 시간당 단가) × 730`, 마지막에만 센트 단위 HALF_UP이다.
참조 t3.xlarge→t3.medium은 `0.208000 / 0.052000`, 월 `113.88 USD`다.

| 출처 | AI 현재 / 목표 단가 | 서버 또는 검증된 산술 결과 | 참조 대비 |
| --- | --- | ---: | ---: |
| 기존 단가 쌍 확대 A7/8 | 0.235200 / 0.052800 | 133.15 USD | +16.92% |
| v0.9.1 서비스 A7/6 | 0.230400 / 0.057600 | 126.14 USD | +10.77% |
| v0.9.1 서비스 A1/6 | 0.230400 / 0.052800 | 129.65 USD | +13.85% |
| 동시 비교 v0.9.0 A7/4 | 0.249600 / 0.062400 | 136.66 USD | +20.00% |
| 동시 비교 v0.9.1 A1/1 | 0.166400 / 0.052800 | 82.93 USD | −27.18% |

동시 비교의 산술은 실패 사례를 포함해 60/60 정합했다. 잘못된 단가 쌍은 서버 계산으로 옮겨도 같은 오차를 만든다.
두 단가의 비율이 일정해도 절대 가격이 틀릴 수 있고, 두 단가의 오차 방향이 다르면 차액의 상대 오차가 더 커질 수 있다.

### 3.2 절감액 오차와 단가 오차는 다른 지표다

현재 [평가 명세](../../spec.json)는 절감액 과대 +10%·과소 −20%, 최소 절대 허용폭 1 USD,
센트 반올림, 산출률 95% 이상, 허용 밖 추정·계약 오류 0건을 요구한다.
참조는 2026-09-15에 확보한 AWS 서울 Linux·Shared·OnDemand 컴퓨팅 가격 스냅샷이다.
현재 가격 조회 결과나 실제 청구서·조치 후 실측 비용은 아니다.

- 113.88 USD의 허용 구간은 91.10~125.27 USD다.
- 56.94 USD의 허용 구간은 45.55~62.63 USD다.
- 반올림된 45.55 USD를 원비율로 나누면 −20%를 약간 넘지만, 사전에 정한 센트 경계에는 통과한다.
- v0.9.0의 **22/60**은 한쪽 이상 단가가 ±10% 진단에서 벗어난 회차 수다. 절감액 실패 22건이나 절감액 −10~−20% 구간 22건이라는 뜻이 아니다.
- 서버 계산으로 나온 `ESTIMATED`는 구조화된 추정의 수용 상태다. AWS 단가 정확성 승인 상태가 아니다.

### 3.3 공개 explanation은 CoT가 아니다

설명에 서울·Linux·공유형·온디맨드가 맞게 적혀 있어도 단가가 어긋났다.
설명문은 공개 산출 근거이며 모델 내부 추론의 기록이 아니다. 내부 CoT는 수집하지 않았다.
현재 확인 가능한 것은 어떤 출력 필드가 기준에서 벗어났는지와 그 오차가 계산에 미친 영향까지다.
다른 리전 요금을 기억했다거나 특정 숫자에 고정됐다는 설명은 검증되지 않은 가설이다.

### 3.4 거부 진단은 거부 뒤에도 남아야 한다

v0.6.0은 정규화된 INVALID만 저장해 어떤 필드에서 왜 거부됐는지 알 수 없었다.
이후에는 필드 위치와 검증 규칙을 남겨 숫자 파싱 거부·리전 불일치·단가 오차를 구분했다.
다만 거부된 원문을 보존하지 않은 과거 결과의 실제 문자열은 복원할 수 없다.
진단 항목을 보강했다는 사실을 과거 거부 원인의 해명으로 보고하지 않는다.

### 3.5 호출 분리와 호출 배치는 별도 결정이다

가격 전용 호출에서 관찰한 개선 신호를 보고 실제 3호출 실험으로 확대한 것은 검증 가능한 단계였다.
하지만 그 세 번째 호출을 **FinOps 그래프 안, 실행 가드레일 앞에 둘 필요**까지 입증한 것은 아니었다.
현재 절감액은 조치 선택·실행 적합성 판정에 쓰이지 않는다.

가드레일은 [Workflow의 실행 명령](../../../../../workflows.py)에 포함되는 런북·대상·파라미터·근거 ID를 검사한다.
절감액은 그 명령에 없다. [단가 수용 계층](../../../../savings.py)은 형식·문맥·산술을 검사하지만 실제 요금과 대조하지 않는다.
따라서 이번에는 **가드레일을 통과한 후보만 후속 단가 호출의 대상**으로 정했다.
이 순서 변경은 거절 후보의 불필요한 호출과 책임 결합을 줄이는 설계이며, 단가 정확도가 향상됐다는 실험 결과는 아니다.

이 수치는 과거 기록이며 이번 문서 정리에서 테스트를 다시 실행한 결과가 아니다.

## 6. 실험 운영에서 유지할 원칙

1. 역할·소비 시점·실패 영향을 정한 뒤 모델 출력과 호출 위치를 정한다. 호출 분리 실험의 신호를 서비스 배치 결정과 합치지 않는다.
2. 입력·프롬프트·출력 스키마의 실제 순서·채점 버전·호출 순서·중단 조건을 고정한다. 여러 축을 바꾼 실행에서는 개별 인과 효과를 주장하지 않는다.
3. 실패·UNAVAILABLE·계약 거부를 분모에 남긴다. 산출된 결과만으로 정확도를 높여 보이지 않는다.
4. 평가 기준을 바꾸면 새 채점 결과로 남기고 이전 판정을 보존한다. 실패 출력을 성공할 때까지 교체하거나 가격을 답지에 맞춰 보정하지 않는다.
5. 60/60처럼 한 라운드의 무실패는 그 조건의 관측 결과다. 후속 실패를 지우거나 모든 상황의 신뢰도로 확대하지 않는다.
6. 원래 승인된 라운드가 끝나면 미사용 호출을 다음 실험으로 넘기지 않는다. 마지막 60호출은 소진됐고 새 라운드 승인은 없다.
7. usage 기반 비용 추정과 실제 청구액을 구분한다. 응답 모델 별칭은 날짜가 고정된 모델 스냅샷이 아니다.

## 7. 다음 결정의 기준

우선 호출 위치를 바로잡고 기존 단가 요청을 유지한 상태에서 무료 회귀를 확인한다.
그 뒤 단가 품질 실험과 서비스 대표 경로 검증의 목적·입력·호출 수를 각각 계획한다.
가드레일 통과를 가격 보증으로 표시하거나, 구조 변경만으로 과거 가격 실패가 해결됐다고 판정하지 않는다.

원래 이슈와 SSOT에는 “추천 호출에서 AI가 금액과 근거 생성”이라는 설명이 있었다.
이슈 본문은 2026-09-16에 “가드레일 통과 후 AI 단가 추정·서버 계산”으로 갱신했다.
SSOT의 범위·공개 API 설명은 PM의 갱신 절차로 연결하며 이 회고에서 팀 확정본을 대신하지 않는다.
