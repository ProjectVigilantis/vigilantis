## 배경

2026-09-07 PM 결정으로 조치별 절감 예상이 MVP에 편입됐다. 자산 인스턴스 수정 추천의 예상 절감액과 산출 근거를 구조화해 저장하고, 조회에서는 저장본을 재사용하는 범위다.

구현 방향은 **FinOps 조치 후보 생성 → 실행 가드레일 → 통과한 RIGHTSIZING 후보의 단가 추정 → 서버 절감액 계산 → 저장·조회**로 정리한다. 절감액은 조치 선택이나 실행 가드레일의 입력으로 쓰이지 않으므로, 가드레일 통과 뒤 해당 후보에 붙인다.

작업 브랜치에는 단가 계약·서버 계산·저장·조회가 구현돼 있지만 현재 단가 호출은 그래프 내부에 있다. 호출 순서를 정리하고, 남은 단가 품질과 최종 서비스 경로를 검증한다.

## 할 일

- FinOps 그래프는 요약·조치 후보 생성과 출력 계약 검사까지 담당하도록 정리한다. 대상과 목표 인스턴스 타입은 기존 서버 계산 규칙을 유지한다.
- Workflow가 후보별 실행 가드레일을 수행한 뒤, **PASS인 `RUNBOOK_EC2_RIGHTSIZING` 후보만** 별도 단가 호출로 넘긴다. 가드레일 거절·무제안·비대상 런북·SecOps에서는 호출하지 않는다.
- 현재 자산 사양·리전·과금 가정과 통과한 후보의 대상·목표 사양을 연결한다. AI는 현재·목표 시간당 단가와 추정 근거를 내고, 서버가 `(현재 단가 − 목표 단가) × 730`을 계산·반올림한다.
- 새 LangGraph 없이 기존 AIModelClient를 쓰는 독립 호출 함수로 연결한다. 호출 순서·실패 처리·트랜잭션은 Workflow가 소유하고, 모델·AWS 호출 동안 DB 트랜잭션을 열어 두지 않는다.
- 통화·산정 기간·금액 정밀도·과금 가정과 추정 출처를 저장·조회 계약으로 유지한다. 금액·근거를 실행 `parameters`, 서버 파생 `display_parameters`, 검증된 실행 명령에 섞지 않는다.
- 정상 추정·산출 불가·호출 실패·계약 오류·저장 불가를 구분한다. 절감 예상 실패는 추정 상태와 사유에 남기고, 통과한 조치 후보와 가드레일 결과를 보존한다. 미산출을 `0`으로 채우지 않는다.
- 후보·가드레일 결과·절감 예상을 기존 저장·상세 API 경로에 연결한다. 기존 후보와 적용 대상이 아닌 런북의 null 호환성을 유지하며, 반복 조회·재시작 후 조회에서 AI를 재호출하지 않는다.
- FinOps 요약·추천과 단가 추정의 지문·호출 수·계측을 분리한다. 분석 회수 시간에는 그래프 뒤 단가 호출까지 포함한다.
- 호출 위치를 옮길 때는 단가 프롬프트와 출력 스키마를 유지한다. 요약·추천은 승인 기준선과 실제 요청을 대조해 재사용 가능 여부를 확인하고, 필요한 변경이 남으면 해당 재통과 절차를 수행한다.
- 서비스 입력과 일치하는 고정 평가 세트·가격 대조 근거로 단가 품질을 독립 계측한다. 절감액 과대 +10%·과소 −20%, 최소 허용폭 1 USD·센트 반올림과 산출률 기준을 적용한다. 개별 단가 ±10%는 별도 진단으로 기록한다.
- 산술 정합성·대상 결속·실행 가드레일 통과와 실제 단가 정확성을 구분해 평가한다. 과거 실패를 보존하고 최종 후보를 사전에 정한 기준으로 검증한다. 유료 실행은 라운드별 최대 호출 수·예상 비용·시간을 제시하고 승인 후 수행한다.
- 가드레일 이후 실제 모델 생성 → DB 저장 → 새 앱 상세 조회의 대표 경로와 FinOps·SecOps 회귀를 확인한다. 입력·설정·지문·판정·검증 한계와 재검증 안내는 `ai/evaluation/savings/`에 남긴다.
- FE가 사용할 응답 계약·예시를 정리하고, AI 단가 추정·서버 계산의 역할과 공개 API 변경을 PM의 SSOT 갱신 절차에 연결한다.

## 예상 변경 파일

- `apps/core-api/ai/agent.py` — 절감 추정 노드 분리, 요약·후보 전용 그래프·지문·호출 수 정리.
- `apps/core-api/ai/savings.py` — 독립 단가 호출, 후보 문맥 검증, 서버 계산과 실패 분류.
- `apps/core-api/agent_dispatcher.py` — 후속 호출에 필요한 모델·입력 전달, 출력 검사와 전체 분석 호출 상한 정리.
- `apps/core-api/workflows.py` — 가드레일 통과 후 단가 호출·후보 보존·최종 저장 순서.
- `packages/schemas/agents.py`, `packages/schemas/candidates.py`, `packages/schemas/savings.py` — 그래프 초안·저장 후보·절감 추정 계약의 책임과 호환성.
- `packages/schemas/api/incidents.py` — 추천 항목의 절감액·근거 응답 계약.
- `apps/core-api/db/models.py`, `apps/core-api/db/mappers.py`, `apps/core-api/db/migrations/versions/` — 저장 필드·매핑·기존 데이터 처리. 이미 작성한 저장 변경을 재사용하고 migration 연결을 확인한다.
- `apps/core-api/routers/incidents.py` — 상세 API에 저장된 절감 예상 반환.
- `apps/core-api/ai/evaluation/savings/`, `scripts/savings_eval.py`, `scripts/finops_eval.py` — 독립 단가 계측과 서비스 대표 검증, 호출 규모·판정·실험 기록.
- `packages/schemas/tests/`, `apps/core-api/ai/tests/` — 계약·계산·그래프·모델 요청·계측 도구 검증.
- `apps/core-api/db/tests/`, `apps/core-api/tests/` — 호출 순서·미호출·실패 보존·저장·조회·기존 데이터 호환 검증.

#324에서 정리한 `ai/evaluation/common/`과 `summary/`를 재사용한다. 같은 파일의 진행 중 변경을 대조하고 공통 계측·summary 이관을 중복 구현하지 않는다.

## 완료 조건

- [ ] 실행 가드레일 통과 전에는 단가 호출이 없고, 통과한 RIGHTSIZING 후보에만 호출한다.
- [ ] AI가 추정한 두 단가로 서버가 절감액을 계산하며, 대상·변경 전후 사양과 해당 후보가 일치한다.
- [ ] 추정 실패·산출 불가·저장 불가가 통과한 조치 후보·가드레일 결과·실행 명령을 훼손하지 않는다.
- [ ] 실제 서비스 입력에서 가드레일 이후 모델 생성·DB 저장·새 앱 상세 API 조회까지 이어지는 대표 경로가 검증된다.
- [ ] 반복 조회·재시작 후 조회에서 저장본을 제공하고 추가 AI 호출이 발생하지 않는다.
- [ ] 기존 후보·비대상 런북·SecOps의 호환성과 미호출 조건이 유지된다.
- [ ] 계측 도구가 알려진 결함을 검출하고 최종 단가 후보가 사전에 정한 품질·산출률 기준을 충족한다.
- [ ] 평가 영역에 입력·모델 설정·프롬프트·채점 지문, 결과·과거 실패·검증 한계·재검증 안내가 남는다.
- [ ] 기존 FinOps 기준선과 실제 요청의 동일성 또는 필요한 재통과가 확인되고, 관련 회귀·필수 통합 테스트가 통과한다.
- [ ] FE가 사용할 응답 계약과 예시가 정리된다.
