# 기존 3호출 후보: 180호출 검증 결과

**결론: 현재 후보는 v1.0.0 확정 보류다.** 60회 중 절감액 PASS 52, 과대 추정 1,
숫자 파싱 거부 7이었다. 산출률 53/60 = **88.3%**로 기준 95%에 미달했고,
과대 추정은 **+16.92%**로 재발했다.

모델 생성 라운드는 승인된 180호출을 모두 완료했다. 실행 완료와 품질 합격은 별개다.

## 1. 실행 조건

| 항목 | 실제 실행 |
| --- | --- |
| 후보 | 기존 단가 쌍 방식 1개, 요약 → 추천 → 절감 예상 |
| 프롬프트 | v0.7.0 3호출 후보 그대로; v0.8.0 비교의 기존 가격 조건과 동일 |
| 모델 | gpt-5.6-luna / low, temperature 미지정 |
| 입력 | A1·A7·A11·A12·A14·A16 각각 10회 |
| 호출 | 180/180, 단계별 60회; 재시도 0회 |
| 응답 | SDK 구조화 출력 수신 180회, 호출·전송 실패 0회 |
| 소요 시간 | 588.491초, 약 9분 48초 |
| 토큰 | 입력 319,491 / 출력 43,926 / 입력 중 캐시 233,543 |
| 비용 추정 | 캐시 할인 미적용 **0.1166094 USD**, 응답의 캐시 사용량 적용 **0.07457166 USD** |

비용은 응답 usage와 [공식 Luna 단가](https://developers.openai.com/api/docs/models/gpt-5.6-luna)의
입력 0.20 / 캐시 입력 0.02 / 출력 1.20 USD per million tokens로 계산했다. 실제 청구액은 아니다.
요약 판정자 호출은 승인 범위에 없어 실행하지 않았다.

## 2. 가격·산출률 결과

평가 명세는 [spec.json](../../spec.json) v0.2.0 그대로다.
과대 +10% / 과소 −20%, 최소 허용 금액 1 USD, 센트 단위 반올림과 산출률 95%를 유지했다.

| 케이스 | PASS | 과대 추정 | 숫자 파싱 거부 | 숫자 산출 |
| --- | ---: | ---: | ---: | ---: |
| A1 | 10 | 0 | 0 | 10/10 |
| A7 | 8 | 1 | 1 | 9/10 |
| A11 | 8 | 0 | 2 | 8/10 |
| A12 | 10 | 0 | 0 | 10/10 |
| A14 | 8 | 0 | 2 | 8/10 |
| A16 | 8 | 0 | 2 | 8/10 |
| 합계 | **52** | **1** | **7** | **53/60** |

- 전체 회차 중 PASS는 52/60 = 86.7%다. 실패를 분모에서 빼지 않았다.
- 단가 각각의 ±10% 정확도 진단은 10건에서 벗어났다. 이 중 9건은 절감액 기준에는 PASS다.
  절감액 통과가 현재·목표 단가 각각의 정확도를 보장하지 않는다는 사례다.
- UNAVAILABLE, 후보 누락, 그래프 FAILED는 모두 0회다.
- 숫자로 산출된 53건은 대상·리전·목표 타입·과금 가정과 산식 계약을 통과했다.
  그중 1건의 단가가 부정확해 절감액 허용 범위를 넘었다.

## 3. 과대 추정: A7의 8번째 실행

| 항목 | 모델 출력 | AWS 평가 참조 |
| --- | ---: | ---: |
| 현재 t3.xlarge 단가, USD/시간 | 0.235200 | 0.208000 |
| 목표 t3.medium 단가, USD/시간 | 0.052800 | 0.052000 |
| 월 절감액, USD | 133.15 | 113.88 |

`(0.235200 − 0.052800) × 730 = 133.152 → 133.15`로 **산술은 맞다**.
현재 단가 오차가 절감액에 +19.856 USD, 목표 단가 오차가 −0.584 USD를 더했고,
반올림 후 차이는 **+19.27 USD / +16.92%**다. 허용 상한 125.27 USD를 초과했다.

앞선 v0.7.0 A1/1의 +13.85%에 이어 같은 단가 쌍 방식에서 과대 추정이 재발했다.
관찰 가능한 오류 위치는 현재 단가 출력이다. 모델이 그 단가를 선택한 내부 이유는 알 수 없다.
CoT는 수집하지 않았고 공개 `explanation`을 내부 사고 과정의 기록으로 해석하지 않는다.

## 4. 숫자 파싱 거부 7건

- A16/2, A14/2, A11/2, A11/3, A16/4, A14/4, A7/10.
- 모두 `amount`, `basis.current_hourly_rate`, `basis.target_hourly_rate`에서
  `decimal_parsing`이 기록됐다. 리전 불일치나 산식 불일치와는 다른 오류다.
- SDK의 첫 출력 계약은 문자열을 수용했지만, 서버의 숫자 계약으로 변환할 때 거절됐다.
- 거절된 원값은 보존하지 않았으므로 통화 기호·단위·기타 문자열 중 어떤 형태였는지는 모른다.
- 최종 절감 예상은 `INVALID`, 금액과 근거는 null이다. 요약과 실행 후보는 유지됐다.

초반에는 t3.large → t3.small에서만 관찰됐지만 마지막 A7/10에서
t3.xlarge → t3.medium에도 발생했다. 특정 사양 조합에만 생긴다고 결론 내릴 수 없다.

## 5. 흐름과 공개 설명 검토

### 실제 모델 호출에서 확인한 범위

| 항목 | 결과 |
| --- | --- |
| 새 요약·새 추천·새 절감 예상 | 각 단계 60회 |
| 그래프 실패 / 후보 누락 | 0 / 0 |
| 자동 요약 사실 검사 | 60회 중 입력 밖 숫자·식별자 오류 0 |
| 실행 관련 필드 반복 일치 | 36/36 |
| 첫 줄 입력값 인용 | 60/60 |
| 되읽기 진단 | 60회 중 20회, 180줄 중 20줄 |
| 요약 복원·결함 판정자 짝 비교 | 미실행 |

자동 사실 검사가 의미 품질 전체를 판정하지는 않는다. 60개 요약과 53개 공개 절감 근거를
직접 읽은 진단은 [public-output-review.json](public-output-review.json)에 남겼다.
이는 설정된 기준선 판정자의 짝 비교나 사람 전문가 검토를 대신하지 않는다.

- A11/1·A14/2·A12/2·A1/2는 과대 스펙을 확정하는 표현을 썼다.
- 요약 8건에 `available_actions`라는 내부 필드명이 노출됐다.
- 공개 절감 근거 3건은 “실제 요금이 모델 지식에 기반한다”는 표현을 써서
  추정 단가와 실제 요금의 구분이 흐려졌다.

### 저장·조회 경계

실행 전 로컬 PostgreSQL·LocalStack 환경에서 Dispatcher·DB 매핑·SecOps 회귀
**55개 통과, 실패 0, skip 0**을 확인했다. 이 안에 2호출 서비스와 3호출 후보의
정상·INVALID 저장, 새 앱·새 ORM Session의 재조회, 추가 모델 호출 없음 검증이 포함된다.

이 테스트는 대역 모델을 사용했고 3호출 후보를 테스트에서 Dispatcher에 주입했다.
이번 180호출은 Golden 입력의 모델 생성 파이프라인이며, 60개 결과를 각각 실제 DB에
저장한 실행이나 서비스 기본 그래프의 3호출 전환을 뜻하지 않는다.

## 6. 후속 설계 제안: 단가 추정과 산술 분리

사용자가 제기한 서버 계산 방향을 다음과 같이 정리한다. **이번 라운드 이후의 제안이며 아직 구현하지 않았다.**

| 역할 | 제안 |
| --- | --- |
| AI | 현재·목표 단가와 단가 추정 근거 생성 |
| 서버 | 서버가 정한 대상·목표 사양에 맞는 단가인지 검증하고, `(현재 단가 − 목표 단가) × 730` 계산·반올림·저장 |
| FE | API가 반환한 저장 금액 표시 |

단가의 AWS 가격 정확도와 서버의 대상·숫자 형식 검증은 구분한다. 서버 계산 결과도
AI 추정 단가를 사용한 **추정값**이며 검증된 실제 청구액이 아니다.

현재 [SSOT](../../../../../../../docs/PROJECT_STATUS.md)는 “금액과 산출 근거를 모두 AI가 낸다”고
정해 두었다. 현재 구현은 이를 따른다. 서버 계산으로 바꾸면 AI 원시 출력에서 `amount`와
금액 산술 지시를 제거하고 서버 수용 계층에서 금액을 만들 수 있다. 공개 응답 `amount`와
기존 저장·조회 구조는 유지할 수 있으며, 산출 주체 설명은 새 역할에 맞게 정리할 내용이다.

저장된 단가만으로 53건을 다시 계산해 보니 **53건 모두 현재 금액과 같았다**.
과대 추정 133.15 USD도 그대로다. 숫자 파싱 거부 7건은 단가도 숫자로 읽히지 않았으므로
서버 계산만으로 복구할 수 없다. 이 확인은 기존 출력의 재계산이며,
금액 산술 업무를 제거한 새 모델 출력의 품질을 측정한 것은 아니다.

서버 계산 전환과 별도로 **단가 출력 형식과 단가 추정 정확도**를 개선해야 한다.
이번 실패 회차를 성공할 때까지 재호출하거나 가격 허용 범위를 바꾸지는 않았다.
