# 기존 3호출 후보 검증

상태: **실행 준비, 유료 라운드 승인 대기.** 새 모델 호출 0회.

사용자 결정에 따라 현재·목표 단가 한 쌍을 생성하는 기존 방식을 최종 후보로 잡는다.
3호출은 요약 → 추천 → 절감 예상 순서다. 프롬프트는 기존 `v0.7.0` 그대로이며,
v0.8.0 비교의 기존 조건과 같은 가격 프롬프트를 사용한다. `v1.0.0` 확정은 보류한다.

## 남은 과대 추정에서 확인한 것

[원자료](../20260915-v0.7.0-three-call-2/raw.json)의 A1/1을 현재 계약으로 재생한 결과는
`ESTIMATED`, 독립 가격 채점은 `PRICE_DEVIATION`이다.
[진단 수치](diagnosis.json)에 원자료 지문과 재생 결과를 기록했다.

| 값 | 모델 출력 | 평가용 AWS 참조 |
| --- | ---: | ---: |
| 현재 t3.xlarge 단가, USD/시간 | 0.230400 | 0.208000 |
| 목표 t3.medium 단가, USD/시간 | 0.052800 | 0.052000 |
| 월 절감 예상, USD | 129.65 | 113.88 |

- `(0.230400 − 0.052800) × 730 = 129.648`, 센트 반올림은 129.65로 맞는다.
- 현재 단가 오차가 절감액에 +16.352 USD, 목표 단가 오차가 −0.584 USD를 더했다.
  최종 차이는 +15.77 USD, 참조 대비 **+13.85%**다. 허용 상한 125.27 USD를 넘는다.
- 서버가 정한 목표 타입·대상·리전, 산식은 일치한다. 관찰한 오류 위치는 생성된 단가다.
- **모델이 왜 그 단가를 선택했는지는 모른다.** 단가 기억 오류나 과금 문맥 혼동은 미확인 가설이다.
- 내부 CoT는 수집하지 않았다. `explanation`은 공개 산출 근거이며 내부 추론의 기록으로 취급하지 않는다.
- 서버 계약 수용은 가격 정확도 인증이 아니다. 이 출력은 계약에 맞아 저장 가능하지만 평가 기준에는 실패한다.

단가 선택의 내부 이유를 확인한 것처럼 프롬프트를 고치지 않는다. 현재 후보를 고정하고
전체 입력에서 오차 분포·재발과 흐름 회귀를 측정한다. 이전 실패는 새 결과와 함께 남기며,
새 회차에서 실패가 없다는 이유만으로 과대 추정 문제가 해결됐다고 판정하지 않는다.

## 준비한 다음 라운드

| 항목 | 범위 |
| --- | --- |
| 비교 열 | 기존 후보 1개 |
| 모델·설정 | gpt-5.6-luna / low, temperature 미지정 |
| 입력 | A1·A7·A11·A12·A14·A16, 각각 10회 |
| 생성 | 60개 파이프라인, 최대 180호출 |
| 프롬프트 | 기존 요약·추천·가격 전용 프롬프트 유지 |
| 시간·비용 예상 | 10~15분, 캐시 할인 미적용 0.12~0.25 USD |
| 재시도 | SDK·앱 모두 0회, 중단한 예산 재배정 없음 |
| 중단 | 요청·인증·전송 오류나 실행기 오류면 중단하고 기록 보존 |
| 품질 실패 | 계획한 나머지 입력까지 측정하고 실패도 분모에 포함 |

비용은 직전 18호출의 61초·0.0114884 USD와
[공식 Luna 단가](https://developers.openai.com/api/docs/models/gpt-5.6-luna)를 바탕으로 확장한 예상이다.
실제 청구액이나 실행 시간 상한을 뜻하지 않는다.

### 이번 라운드가 확인하는 것

1. 매회 새 요약·추천·절감 예상을 생성하고 현재 계약으로 수용한다.
2. 절감액 과대 +10% / 과소 −20%, 최소 허용 금액 1 USD, 산출률 95%를 그대로 적용한다.
3. 후보·근거 ID·서버 목표 사양의 반복 일치와 자동 요약 사실 검사를 수행한다.
4. 단가별 오차는 별도 진단으로 남긴다. 평가 참조 가격을 모델 입력이나 서비스에 주입하지 않는다.
5. 모든 실패와 단가 조합별 공개 설명을 검토한다. 자유 서술 의미 검토와 자동 사실 검사는 구분한다.

### 전체 완료에 남는 검증

- 로컬 PostgreSQL 저장·새 앱/새 Session 재조회·추가 모델 호출 없음은 대역 모델로 별도 검증한다.
  3호출 후보는 테스트에서 Dispatcher에 주입하므로 서비스 기본 그래프 전환의 증거가 아니다.
- 요약 복원 및 결함 판정은 기존 승인 원자료와 같은 판정 패스로 비교해야 한다.
  이 계획의 180호출에는 판정자 호출을 포함하지 않는다. 원자료를 확보한 뒤 별도 라운드로 준비한다.
- 가격 품질, 요약 품질, 실제 DB 호환성이 각각 확인되기 전 서비스 기본 3호출·승인 스냅샷·v1.0.0을 확정하지 않는다.
- 고정한 서울 T3 6케이스의 평가이며 실제 청구액, 다른 리전·인스턴스군의 정확도까지 보장하지 않는다.

## 실행 및 보관

[run_round.py](run_round.py)의 기본 실행은 네트워크 없는 사전 확인이다.
[preflight.json](preflight.json)에 입력·프롬프트·관련 구현과 채점 명세 지문을 고정했다.
유료 실행은 해당 라운드 승인 후 `--execute-approved-round`를 명시한다.

실행 후 `raw.json`, `metadata.json`, `scored.json`, `flow-scored.json`을 매 회차 저장한다.
원본 제공자 응답·거절된 원값·예외 메시지·CoT·키는 저장하지 않는다.
기존 기록이 있으면 같은 폴더에서 다시 실행하지 않는다.
