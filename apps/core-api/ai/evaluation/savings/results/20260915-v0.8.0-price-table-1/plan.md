# v0.8.0 가격표 비교 — 실행 전 고정 계획

사용자 승인: “0.8.0 실험과 모델 호출 승인합니다.” 기존 골든 입력·프롬프트 외부 전송과 기본 체크아웃 `.env` 키 사용 승인도 적용한다.

## 목적과 변경

서버는 대상·리전·현재 사양·목표 사양을 결정한다. A1은 `t3.xlarge → t3.medium`, A11은 `t3.large → t3.small`이다. AI는 해당 변경의 단가·월 금액·공개 산출 근거를 생성하며 목표 사양을 다시 선택하지 않는다.

- 대조군 `pair`: 기존 가격 전용 프롬프트와 `ProposedSavingsEstimate` 출력.
- 개선안 `table`: 같은 리전·Linux·Shared·OnDemand 조건의 T3 네 사양 가격표를 먼저 생성하고, 서버가 지정한 두 사양의 월 차액과 공개 근거를 작성한다. 서버 코드는 입력의 사양으로 표의 행을 선택하고 기존 수용 계약을 적용한다.
- 가격표와 기존 방식의 출력·프롬프트를 함께 바꾸는 실험이다. 차이가 나도 표 구조만의 인과 효과로 단정하지 않는다.
- 평가 참조 단가는 모델 입력에 포함하지 않는다. 산출값을 참조 가격으로 보정하지 않는다.

## 고정 조건

`gpt-5.6-luna`, reasoning `low`, 한국어, temperature 미지정. 입력 6건 전체 지문과 `spec.json` v1은 고정하고 A1·A11만 각 3회씩 선택한다. 모든 호출은 서로 독립적이며 이전 응답을 재사용하지 않는다.

1단계는 세 번째 가격 호출만 두 조건 × 두 케이스 × 3회, **최대 12호출**이다. 순서는 A1/1 pair→table, A11/1 table→pair, A11/2 pair→table, A1/2 table→pair, A1/3 pair→table, A11/3 table→pair로 고정한다. 예상 약 1분, $0.008–$0.015. SDK 재시도 0, 호출 시도 1, 타임아웃 30초.

## 판정과 중단

- 기존 기준 그대로 현재·목표 단가 각각 참조 대비 오차 ≤10%, 월 금액 오차 ≤max($1, 10%), 계약 오류 0건, 미산출을 정확도 개선으로 세지 않는다.
- 각 조건 6회 모두 PASS여야 이 작은 진단을 통과한다. 표의 다른 두 행은 별도 진단이며 선택한 두 사양의 기존 판정에 합치지 않는다.
- 품질 실패에도 예정된 12회는 수집한다. 요청·전송·예상 밖 실행기 오류에는 즉시 중단하고 남은 호출을 재배정하지 않는다. 응답 파싱 실패는 분모에 남기고 다음 독립 호출을 진행한다.
- 결과 폴더가 이미 실행됐으면 재실행하지 않는다. 원본 거절 값·제공자 응답·전체 프롬프트·예외 메시지는 저장하지 않는다. 수용된 공개 출력, 숫자 검증을 통과한 표, 필드·규칙 진단, 토큰과 시간만 기록한다.
- 개선안이 **6/6 PASS이면** 승인 계획의 다음 단계로 새 요약→추천→가격표 전체 파이프라인 A1·A11 각 3회, **최대 18호출**을 별도 라운드에서 실행한다. 한 건이라도 미달이면 다음 단계는 실행하지 않는다.
- 이번 진단은 전체 6건 × 10회 기준선·요약 회귀·서비스 3호출 채택을 승인하지 않는다.

## 실행 파일

`run_round.py` 기본 실행은 네트워크 없이 입력·명세·코드·프롬프트 지문만 확인한다. `--execute-approved-round`에서만 승인된 공식 OpenAI 엔드포인트를 호출한다. `pair-raw.json`·`table-raw.json`과 각 채점 결과를 분리하고 `metadata.json`에 실제 호출 순서·비용·시간을 함께 보존한다.
