# v0.9.0·v0.9.1 단가 비교 결과

**60호출 완료. 두 버전 모두 29/30 통과했지만 이탈 방향은 다르다.**
v0.9.0은 절감액 과대 추정 1건(+20.00%), v0.9.1은 과소 추정 1건(−27.18%)이다.
두 버전 모두 사전에 정한 진단 기준을 충족하지 못했다. v1.0.0 확정은 보류한다.

## 같은 라운드에서 확인한 결과

| 항목 | v0.9.0 | v0.9.1 |
|---|---:|---:|
| 호출·추정 산출 | 30/30 | 30/30 |
| 절감액 허용 구간 통과 | 29/30 | 29/30 |
| 과대 +10% 상한 이탈 | **1건** | **0건** |
| 과소 −20% 하한 이탈 | 0건 | **1건** |
| 호출·파싱·서버 계약 오류 | 0 | 0 |
| 최대 절감액 과대 오차 | +20.00% | +10.00% (센트 경계 내) |
| 단가 각각 ±10% 진단 이탈 | 7건 | 8건 |
| 절감액 과소 허용 하한과 일치 | 4건 | 4건 |

산출률 95%, 가격 이탈·계약 오류 0건을 요구한 [기존 기준](../../spec.json)을 유지했다.
29/30이라는 합계만으로 두 버전의 오류 영향을 같게 보지 않는다.
v0.9.0의 오류는 얻을 수 있는 절감을 부풀리고, v0.9.1의 오류는 절감을 보수적으로 낮추지만
사용자가 정한 −20% 허용 범위를 넘었다.

|---|---|---|
| A1 | 10/10 통과 | 9/10 통과, 반복 1에서 과소 이탈 |
| A7 | 9/10 통과, 반복 4에서 과대 이탈 | 10/10 통과 |

## 이탈한 두 건의 수치

두 사례 모두 서울 리전, Linux·공유 테넌시·온디맨드, t3.xlarge→t3.medium 조건이다.
평가 참조 단가는 현재 **0.208000 USD/h**, 목표 **0.052000 USD/h**다.
참조 월 절감액은 **113.88 USD**, 센트 단위 허용 구간은 **91.10~125.27 USD**다.
참조값은 고정한 AWS 가격 스냅샷에 근거하며 실제 사용자의 청구액을 뜻하지 않는다.

| 항목 | v0.9.0 A7 / 반복 4 | v0.9.1 A1 / 반복 1 |
|---|---:|---:|
| 전체 호출 번호 | 22 | 2 |
| AI 현재 단가 | 0.249600 | 0.166400 |
| AI 목표 단가 | 0.062400 | 0.052800 |
| 현재 단가의 참조 대비 오차 | +20.00% | −20.00% |
| 목표 단가의 참조 대비 오차 | +20.00% | +1.54% |
| 서버 계산 월 절감액 | 136.66 USD | 82.93 USD |
| 참조 월 절감액 대비 차이 | +22.78 USD | −30.95 USD |
| 절감액 오차 | **+20.00%** | **−27.18%** |
| 허용 경계 초과분 | 상한보다 11.39 USD 큼 | 하한보다 8.17 USD 작음 |

- **v0.9.0:** 두 단가가 함께 20% 높았다. 단가 간 비율은 유지됐어도 절감액은 과대였다.
- **v0.9.1:** 현재 단가는 20% 낮고 목표 단가는 1.54% 높았다. 두 단가를 빼는 과정에서
  절감액의 과소 편차가 27.18%로 커졌다.
- **서버 계산:** `(현재 단가 - 목표 단가) × 730`과 센트 반올림은 두 실패 사례를 포함해
  **60/60건 정확했다.** 산술·형식 수용이 단가 정확도를 보장하지 않는 사례다.

이 설명은 저장된 단가와 산식을 대조한 결과다. 모델이 그 단가를 선택한 내부 이유는
확인하지 못했다. 내부 추론은 수집하지 않았고, 공개 설명문을 추론 기록으로 해석하지 않는다.

### 반올림 경계와 단가 진단

v0.9.1 A7/3의 125.27 USD는 상한과 같다. 원시 상대 오차는 +10.001756%지만
허용 상한도 센트 반올림한 125.27이므로 기존 규칙상 통과한다.
두 열 각각 4건의 A11 45.55 USD도 반올림된 −20% 하한과 같아 통과한다.

단가 ±10% 진단 이탈은 별도 집계다. v0.9.0의 7건은 높은 단가 1건·낮은 단가만 있는 6건,
v0.9.1의 8건은 모두 낮은 단가가 원인이다. 이것을 절감액 실패 7건·8건으로 읽으면 안 된다.

## 공개 설명 확인

수용된 설명문 60건을 읽었다. 리전·Linux·공유형·온디맨드·컴퓨팅 비용 범위·제외 항목·
모델 지식 기반 추정이라는 한계에서 입력 조건과 모순되는 진술은 찾지 못했다.
`pricing_source`·`MODEL_KNOWLEDGE`가 설명문에 남은 사례는 양쪽 모두 0/30이었다.
v0.9.1에 추가한 한국어 표현 지시의 효과가 입증됐다고 볼 수는 없다.

현재·목표 사양을 설명문에도 명시한 경우는 v0.9.0 9/30, v0.9.1 16/30이었다.
모든 결과의 구조화된 근거에는 두 사양이 정상 보존됐다. 설명문 지시 충족은 별도 후속이며,
이번 가격 판정을 사후에 바꾸는 기준으로 사용하지 않았다.

## 결론과 후속 범위

1. **v0.9.0으로 되돌려도 과대 문제가 사라진다고 볼 수 없다.** 이전 60/60 통과 뒤에도
   이번 같은 라운드에서 +20% 과대가 재발했다. v0.9.1의 추가 한국어 지시만을 원인으로
   지목할 근거는 확보되지 않았다.
2. **이번 v0.9.1의 과대 이탈 0/30은 해결 확정이 아니다.**
   [앞선 서비스 검증](../20260915-service-adoption-1/report.md)의 과대 2건은 그대로 남는다.
   이번 3개 사례와 앞선 6개 사례를 합산해 새로운 합격률을 만들지 않는다.
3. **후속 제안:** 현재 v0.9.1을 작업 기준으로 유지하면서 단가 쌍을 만드는 방식을 검토한다.
   이번 과소 사례의 현재/목표 단가 편차 차이와, 과거 과대 사례를 함께 재사용해 수정 범위를 정한다.
   두 단가의 비율만 맞추는 것으로는 v0.9.0의 함께 높은 단가 오류를 잡을 수 없다.
4. 서버의 월 절감액 계산, 서비스 3호출 구조, +10%/−20% 평가 기준은 유지한다.
   다음 품질 후보가 정해지면 6개 사례의 서비스 생성·승인 v2와 요약 짝 비교·
   온라인 생성→저장→조회 검증을 이어간다.

이번에 수행한 것은 **3개 사례의 단가 호출 비교**다. 추가 프롬프트 수정·후속 모델 호출·
서비스 기준선 갱신·PR 게시는 수행하지 않았다. 작은 표본으로 두 프롬프트의 인과 효과나
오류율 차이를 확정하지 않는다.
