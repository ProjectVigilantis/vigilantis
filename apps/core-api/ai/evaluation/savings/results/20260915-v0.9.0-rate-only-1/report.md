# v0.9.0: AI 단가 추정·서버 절감액 계산 결과

**승인한 1~3단계를 완료했다. 새 후보는 180호출·60회에서 절감액 기준을 모두 통과했다.**
AI 출력에서 월 절감액을 제거하고 서버가 검증된 형식의 추정 단가로 계산하도록 구현했다.
관련 로컬 검증은 **183개 통과, 실패·skip 0개**다.

최대 절감 과대 추정은 **+4.62%**로 허용 상한 +10% 안에 들어왔다.
다만 **16회가 과소 추정 허용 하한에 걸렸고, 단가 각각 ±10% 진단은 22회에서 벗어났다.**
절감액 기준 통과와 단가 정확도, 요약 의미 품질, 서비스 채택은 각각 구분한다.

## 1. 구현한 역할

| 담당 | 이번 후보의 동작 |
| --- | --- |
| 서버 정책 | AWS 대상·리전·현재 사양·목표 사양과 과금 가정을 정한다 |
| AI | 현재·목표 시간당 단가와 공개 추정 근거를 생성한다 |
| 서버 수용 계층 | 단가 형식·범위·대상 일치를 검증하고 월 절감액을 계산·반올림한다 |
| 저장·조회 | 기존 amount + basis 형태로 저장하고 상세 API에서 같은 값을 반환한다 |
| FE 접점 | API의 저장된 예상 금액을 소비한다. 화면 변경은 이번 범위에 포함되지 않는다 |

산식은 **(현재 시간당 단가 − 목표 시간당 단가) × 730**이다.
Decimal로 계산하고 최종 결과만 센트 단위 ROUND_HALF_UP으로 반올림한다.
예를 들어 0.104000과 0.026000을 받으면 서버 결과는 56.94 USD다.
이 금액도 AI가 추정한 단가에 기반한 예상값이다. 서버가 실제 AWS 가격임을 검증한 값은 아니다.

AI의 ProposedHourlyRates에는 amount가 없다. 단가 문자열은 숫자와 최대 소수 6자리만 허용하며,
이 pattern을 실제 SDK가 보내는 strict 구조화 출력 스키마에도 전달한다.
숫자로 해석할 수 없는 값, 대상 불일치, 음수 절감액, 저장 범위를 넘는 금액 등은 INVALID로 처리한다.
UNAVAILABLE는 두 단가가 모두 null이어야 하고, 서버 대상 문맥 검증도 통과해야 한다.

기존 절감 예상 계약과 저장·조회 필드 형태는 유지했다. 실험 후보는
요약 → 추천 → 단가 추정의 3호출 경로에서 새 서버 계산 함수를 사용한다.
**서비스 기본 그래프는 기존 2호출 v0.5.0 상태다.** 테스트에서만 새 후보를 Dispatcher에 주입했다.

AWS MVP 범위에서 기존 정책을 활용했다. Compute Optimizer는 설계 참고이며
해당 API 연동이나 NCP·Azure용 공통 계층을 추가하지 않았다.

확대 전에 초기 원자료·호출 기록·고정 구현 지문과 확대 조건을 대조했다.

usage 누락은 0회다. 실제 청구액이나 별도로 보고되지 않은 캐시 쓰기 비용을 확인한 값은 아니다.

## 3. 절감액 평가

[spec.json](../../spec.json) v0.2.0을 그대로 적용했다.
과대 +10% / 과소 −20%, 최소 절대 허용폭 1 USD, 센트 반올림, 산출률 95% 조건이다.
평가용 AWS 참조 단가를 AI 입력으로 보내거나 서버에서 추정 단가를 보정하지 않았다.

| 케이스 | 사양 변경 | PASS | 참조 월 절감액 | 산출 범위, USD |
| --- | --- | ---: | ---: | ---: |
| A1 | t3.xlarge → t3.medium | 10/10 | 113.88 | 113.88~115.63 |
| A7 | t3.xlarge → t3.medium | 10/10 | 113.88 | 113.88~115.63 |
| A11 | t3.large → t3.small | 10/10 | 56.94 | 45.55~59.57 |
| A12 | t3.large → t3.small | 10/10 | 56.94 | 45.55~57.82 |
| A14 | t3.large → t3.small | 10/10 | 56.94 | 45.55~59.57 |
| A16 | t3.large → t3.small | 10/10 | 56.94 | 45.55~57.82 |
| 합계 | 6건 × 10회 | **60/60** | | |

- ESTIMATED 60, UNAVAILABLE 0, INVALID 0, 가격 허용 범위 이탈 0.
- 산출률 **100%**, 서버 산술·문맥·가정 검증 **60/60 통과**.
- 최대 과대 추정 사례 A11/2: 단가 0.108800 / 0.027200 → **59.57 USD**.
  참조 56.94보다 **2.63 USD / +4.618897%** 높다.
- 최대 과소 추정 사례 A11/1: 단가 0.083200 / 0.020800 → **45.55 USD**.
  참조 56.94보다 11.39 USD 낮으며, 센트 단위 허용 하한과 같다.

참조 56.94의 −20% 하한은 45.552를 반올림한 **45.55**다.
반올림된 금액으로 비율을 다시 나누면 −20.003512%가 되지만 사전에 정한 센트 단위 판정에는 통과한다.
서버가 하한으로 금액을 잘라 맞춘 결과는 아니다.

### 별도 단가 진단과 직전 후보 비교

단가 각각의 ±10% 진단에서 **22/60회가 이탈**했다.
절감액 하한과 같은 결과도 **16/60회** 있었다.
보수적인 방향을 허용한 절감액 기준에는 합격했지만 현재·목표 비용의 개별 정확도까지 합격한 것은 아니다.

| 항목 | 직전 기존 단가 쌍 후보 | 이번 v0.9.0 |
| --- | ---: | ---: |
| 실행 / 호출 | 60 / 180 | 60 / 180 |
| 절감액 PASS | 52/60 | **60/60** |
| 가격 허용 범위 이탈 | 1 | **0** |
| 숫자 파싱 거부 | 7 | **0** |
| 산출률 | 53/60, 88.3% | **60/60, 100%** |
| 최대 절감 과대 추정 | +16.92% | **+4.62%** |
| 개별 단가 ±10% 진단 이탈 | 숫자 산출 53회 중 10회 | 숫자 산출 60회 중 22회 |

직전 결과는 [기존 후보 180호출 보고서](../20260915-pair-candidate-validation-1/report.md)에 있다.
이번 후보는 amount 제거·숫자 pattern·단가 전용 설명 지시를 함께 바꿨다.
이 표는 두 라운드의 관측 결과이며 각 변경의 독립 효과나 모델 내부 원인을 증명하는 대조 실험은 아니다.

기존 과대 추정 단가 0.2352 / 0.0528을 새 서버 계산 함수에 넣으면 여전히 133.15가 된다.
이 동작도 단위 테스트로 고정했다. **서버 계산은 산술 책임을 맡으며, 부정확한 단가를 가격 정답으로 바꾸지는 않는다.**

## 4. 흐름 검증과 공개 출력 검토

| 확인 범위 | 결과 |
| --- | --- |
| 실제 모델 파이프라인 | 60회 SUCCEEDED, 후보 누락 0 |
| 자동 입력 사실 검사 | 60회 중 입력 밖 숫자·식별자·사양 위반 0 |
| 실행 관련 필드 반복 일치 | 36/36 |
| 첫 줄 입력값 인용 | 60/60 |
| 자동 되읽기 진단 | 60회 중 13회, 180줄 중 13줄 |
| 공개 문장 읽기 | 요약 60개·절감 근거 60개 전체 |
| 승인 요약 판과 정식 짝 비교 | 미실행 |

공개 절감 근거 60개는 모델 지식에 기반한 추정이며 실제 요금 조회 결과와 다르다는 점을 설명했다.
구조화 basis에는 대상과 두 사양이 모두 있지만, 자유 서술에 두 사양명이 항상 반복되지는 않는다.
공개 절감 근거에서 모델이 월 절감액을 직접 계산해 서술한 사례는 관찰하지 않았다.

별도 문장 진단은 [public-output-review.json](public-output-review.json)에 남겼다.

- 요약 10개에 available_actions가, 다른 1개에 net_in_avg·net_out_avg가 노출됐다.
- 절감 근거 3개(A14/5·7·8)에 pricing_source=MODEL_KNOWLEDGE가 그대로 노출됐다.
- A1/3은 “과대 스펙 상태로 확정”, A14/2·A11/6은 현재 사양이 부하보다 크다고
  “확인된다”고 서술했다. 낮은 CPU·네트워크 관측만으로 전체 사양의 과대를 확정하는 표현은 후속 검토 대상이다.

위 내용은 저장된 공개 출력을 읽은 진단이다. 정식 요약 판정자나 전문가 검토를 대신하지 않는다.
내부 CoT는 수집하지 않았으며 공개 explanation을 모델 내부 추론 기록으로 취급하지 않는다.
요약 프롬프트는 이번에 바꾸지 않았다.

## 5. 로컬 검증과 증거 범위

관련 CI 테스트 경로에서 **183 passed / 0 failed / 0 skipped / 1,970 deselected**, 6.79초였다.
선택 범위는 절감 예상, Dispatcher, DB mapper, SecOps 그래프다.
전체 저장소 테스트가 모두 통과했다는 의미는 아니다.

- 수작업 산술 정답, 마지막 단계 반올림, 동률 단가, 잘못된 숫자 형식·문맥·상한·음수 결과를 검증했다.
- 실제 OpenAI SDK의 mock transport에서 strict·pattern·nullable·추가 필드 금지·amount 부재와 low 설정을 확인했다.
- 실제 PostgreSQL에 정상·INVALID·UNAVAILABLE 결과를 저장하고 새 앱·새 ORM Session에서 반복 조회했다.
  조회 시 모델 호출이 늘지 않았다.
- 3호출 테스트는 새 후보를 Dispatcher에 주입하고 모델 대역을 사용했다.
  실계측 60개를 모두 DB에 적재한 실행이나 서비스 기본 그래프 전환의 증거는 아니다.
- 변경 후보·실행기·분석 코드 Ruff는 통과했다.
  Dispatcher 테스트 파일의 기존 30개 진단은 유지됐고 이번 변경에서 추가된 진단은 0개였다.

준비 과정에서 SDK 테스트의 클라이언트 생성 인자 누락 1건을 수정한 뒤 위 결과를 확인했다.
로컬 검증 세부 범위와 기존 진단 비교 방식은 [preparation-verification.json](preparation-verification.json)에 있다.

원자료 재채점, 흐름 집계, 호출별 usage, 초기 사본·확대 기록을 다시 계산해 일치를 확인했다.
실행 전 고정한 구현 19개와 기존 실험 파일 78개도 유지됐다.
기존 서비스·pair·table 프롬프트 지문은 바뀌지 않았다.
