# 후보 A — 식별자 재출력 제거 검증

2026-09-16. [설계](../../plans/20260916-output-simplification.md)의 A를 구현한 첫 라운드다.
사용자는 이 후속 검증에 유료 호출 최대 **80회**를 명시적으로 승인했다.
이번 단가 라운드는 그 안에서 **1열, 최대 60회**로 제한한다. B·재시도·표본 대체에 남은 한도를 쓰지 않는다.

## 고정 조건과 중단

- A1·A7·A11·A12·A14·A16 × 각 10회. 가격 조건은 두 종류다.
- Luna / low, temperature 미지정, SDK 재시도 0, 래퍼 시도 1회, 요청 timeout 30초.
- 기존 입력과 과금 가정 유지. 식별자 네 출력 필드 제거, 프롬프트의 “복사한다”만 “사용한다”로 변경.
- 실제 SDK 직렬화에서 그 차이만 있는지 무료 대조한다. 온라인에서도 각 전송 본문 지문을 전송 직전에 대조한다.
- 기존 명세 v0.2.0 유지: 산출 최소 57/60, 가격 허용 범위 이탈·출력 계약 오류 0건.
- 첫 가격 이탈·출력 계약 오류, 네 번째 UNAVAILABLE에서 즉시 중단한다.
- 호출 장애·실행기 오류는 미완료로 남기고 재시도하지 않는다. 중단된 실행의 재개도 차단한다.
- 모든 시도는 전송 전에 STARTED를 기록한다. 부분 성공만으로 통과를 판정하지 않는다.

## 비용·시간

최대 60회 기준 예상 **0.03~0.06 USD, 4~6분**. 조기 중단 시 실제 사용량은 줄어든다.
직전 동일 모델의 단가 60회는 입력 55,150·출력 20,554토큰, 약 220초였다.
그 사용량에 아래 공식 단가를 적용한 추정은 0.0356948 USD다.
이번 SDK 요청은 사례별 약 3.3KB이며, 입력 크기와 출력 필드가 줄어도 토큰 감소나 시간 단축을 보장하지 않는다.

[공식 Luna 모델 문서](https://developers.openai.com/api/docs/models/gpt-5.6-luna)를 2026-09-16 확인했다.
100만 토큰당 입력 0.20 / 캐시 입력 0.02 / 출력 1.20 USD다.
캐시 쓰기 단가는 비캐시 입력의 1.25배다. SDK가 별도 보고하지 않는 캐시 쓰기·실패 usage와 실제 청구액은 미확인이다.
예상 금액·시간은 보장 상한이 아니며 실행 한도는 60회다.

## 실행 및 기록

worktree 루트의 `.venv/Scripts/python.exe -X utf8`로
`apps/core-api/ai/evaluation/savings/compact_validation.py`를 실행한다.

- 인자 없음: 사전 지문 대조, 키 읽기·외부 호출 없음.
- `--freeze`: 승인 기록·실행 시작 전 계획 고정.
- `--execute-approved`: 실제 사용자 승인 기록과 사전 지문 대조 후 1회만 실행.
- `--analyze`: 저장 결과를 동일 채점기로 오프라인 재채점.

키는 기존에 승인된 기본 체크아웃 `.env`에서 승인·중복 실행 검사를 마친 뒤 읽는다.
Golden 외부 전송 범위는 기존과 같다. 참조 단가를 모델에 제공하지 않는다.
원문 응답·거부 원문·내부 추론·키를 저장하지 않고, 수용된 구조화 추정·검증 위치/규칙·usage·시간을 기록한다.

모델의 문맥 재출력 검사는 제거됐으므로 그 오류가 0건이라는 개선 주장은 하지 않는다.
서버 연결·산술과 가격 정확성은 별도로 보고한다. 가격 통과도 서비스 저장 경로의 온라인 완료를 뜻하지 않는다.

## 조건부 서비스 확인

A가 가격 기준을 충족하고 공개 설명 결함이 없을 때만 두 가격 조건의 실제 생성→가드레일→단가→DB→새 앱 조회를 준비한다.
설계의 최대 6회는 사용자 총 승인 80회 안에 들어가지만, 단가 라운드의 남은 호출을 재시도나 B로 자동 재배정하지 않는다.
서비스 확인을 실행하게 되면 실제 범위·예상 비용·시간을 다시 알리고 누적 호출 수를 함께 기록한다.
이번 단가 라운드가 품질 기준에 미달하면 서비스 편입과 그 추가 호출을 진행하지 않는다.
