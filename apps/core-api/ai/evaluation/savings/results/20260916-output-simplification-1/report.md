# 후보 A 검증 결과 — 두 번째 호출에서 가격 기준 미달

2026-09-16. **A는 채택하지 않는다.** 식별자 재출력을 제거한 후보가 두 번째 호출에서 절감액 과대 허용폭을 넘었다.
사전에 정한 첫 가격 이탈 중단 조건에 따라 **실제 유료 호출 2회**로 종료했다. 60회 전체 평가는 완료하지 않았다.
이는 후보의 0건 이탈 기준을 충족할 수 없다는 판정이며, 일반 실패율이나 기존 버전보다 나빠졌다는 추정은 아니다.

## 가격 결과

두 응답 모두 서울, Linux·Shared·OnDemand, t3.xlarge → t3.medium 조건이다.
고정한 AWS 스냅샷 참조는 0.208000 / 0.052000 USD/h, 월 113.88 USD이며 허용 구간은 91.10~125.27 USD다.
현재 AWS 요금 조회 결과나 실제 고객의 청구액을 뜻하지 않는다.

| 호출 | 사례/반복 | AI 현재 / 목표 단가 USD/h | 서버 계산 월 절감액 | 참조 대비 | 판정 |
| --- | --- | --- | ---: | ---: | --- |
| 1 | A1 / 1 | 0.211200 / 0.052800 | 115.63 USD | +1.54% | 허용 구간 통과 |
| 2 | A7 / 1 | 0.230400 / 0.057600 | 126.14 USD | **+10.77%** | 상한 125.27 USD보다 **0.87 USD 초과** |

A7은 두 단가가 각각 약 10.77% 높았다. 비율이 유지돼도 절대 단가 오류가 절감액 오류로 이어졌다.
이 단가 쌍은 [이전 회고의 v0.9.1 서비스 A7/6](../20260916-retrospective/report.md)에도 기록돼 있다.
식별자 재출력 제거로 이 오류 유형이 없어지지는 않았다. 원인을 모델의 특정 기억·내부 추론으로 단정하지 않는다.

- 산술·형식·저장 수용 계약: **2/2 통과**, 호출·파싱 오류 0건.
- 출력에서 식별자를 제거했으므로 모델 응답의 식별자 일치 검사는 수행하지 않았다. 저장 근거의 식별자는 서버 문맥에서 왔다.
- 공개 설명 2건은 서울·현재/목표 사양·Linux·공유형·온디맨드·제외 비용·모델 추정 한계를 담았다.
  입력 조건과 모순되거나 실제 요금 조회 결과라고 주장하는 문구는 찾지 못했다. 설명이 맞아도 단가가 맞는 것은 아니다.
- 실제 산출은 시도한 2건 중 2건이다. 전체 60회 산출률 95% 기준의 완료 판정은 하지 않는다.
- 전체 고정 세트에는 가격 조건 두 종류가 있지만, 이번 중단 전에는 xlarge → medium 한 종류만 관찰했다.

## 호출·비용 장부

- 사용자 승인: 후속 검증의 유료 호출 최대 **80회**. [승인 기록](approval.json).
- 이 라운드 계획: A 1열, 최대 60회. [고정 계획](plan.md) · [사전 지문](preflight.json).
- 실제: **2회 요청, 2회 응답**. 계획의 나머지 58회 미실행. 사용자 총 한도 중 78회 미사용.
- SDK 재시도 0, 래퍼 1회 시도. 재시도·표본 교체·B 호출·서비스 대표 경로 호출 0회.
- 실행: **2026-09-16 10:10:14~10:10:26 KST**, 11.591초.
- 모델: `gpt-5.6-luna`, reasoning `low`, temperature 미지정. 반환 모델 식별자도 같은 별칭이었다.
- usage: 입력 **1,770**, 출력 **629**, 보고된 캐시 입력 **0**토큰. 두 호출 모두 usage가 있다.
- [공식 단가](https://developers.openai.com/api/docs/models/gpt-5.6-luna)로 계산한 추정 **0.0011088 USD**.
  입력 0.20 / 출력 1.20 USD per 1M tokens를 적용했다. 실제 청구액·별도 미보고 캐시 쓰기 비용은 확인하지 않았다.

처음 실행 요청은 프로세스 생성 전에 자동 승인 검토가 차단했다. 사유는 구체적 입력·목적지의 전송 승인 근거 부족이었다.
공개 저장소 여부와 README의 더미 데이터 명시, 실제 전송할 여섯 입력을 확인해 [전송 검토 자료](transmission-review.json)를 만들었다.
그 근거를 붙인 동일 명령이 승인돼 위 2회가 실행됐다. 최초 차단에서는 모델 요청이 발생하지 않았다.
기존 전송 정책은 더미 ARN의 계정 `123456789012`를 보존하므로, ARN이 마스킹됐다고 주장하지 않는다.
