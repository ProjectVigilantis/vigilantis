## 호출 규모와 요청 지문

- `scripts/finops_eval.py --estimate --repeats 10`: 6사례 × 10회, 그래프 최대 120호출. 단가·가드레일·저장은 실행하지 않는다.
- 독립 `estimate_candidate_savings()`: 대상이 일치하는 후보당 최대 1호출. 6사례 × 10회라면 최대 60호출이다. 새 유료 실행은 별도 라운드 승인 대상이다.
- Dispatcher → Workflow 전체: 통과 RIGHTSIZING 후보가 있을 때 그래프 2 + 단가 1, 최대 3호출. 거절·무제안·비대상·SecOps의 단가 호출은 0회다.
- `scripts/savings_eval.py`는 저장된 절감 예상의 채점기이며 모델 호출은 0회다. 현재 summary 전용 CLI 결과에는 절감 예상이 없어 이 채점의 입력으로 사용할 수 없다.
- `finops_prompt_fingerprint()`는 승인 v2의 기존 직렬화를 유지한다. `finops_request_fingerprint()`는 스키마 순서를 추가로 추적하고, `ai.rate_estimator.savings_prompt_fingerprint()`는 현재 독립 단가 요청만 추적한다. `ai.savings`의 이전 타입·함수는 과거 실험 재현용으로 보존한다.
- [request_snapshot.json](request_snapshot.json)은 고정 6사례의 실제 SDK 요청 지문이다. 승인 v2 코드와 이동 전 서비스 단가 노드에서 MockTransport로 수집했다. 메시지·입력·capabilities·스키마 title/description/필드 순서·Luna/low/temperature 미지정을 함께 대조한다. 승인 스냅샷이나 과거 결과를 새 출력에 맞춰 갱신하지 않았다.

## 현재 평가 기준 — v0.2.0

2026-09-15 사용자 결정으로 절감액의 위험한 방향은 10%를 유지하고 보수적인 방향은 20%까지 허용한다. 현재 평가 명세는 [spec.json](spec.json), 실행 당시 대칭 기준은 [spec-v1.json](spec-v1.json)에 원본 바이트 그대로 보존했다. 평가 명세·채점기 판은 프롬프트 판과 별개다. v0.2.0 기준 변경 당시에는 저장된 결과만 재채점했고, 이후 v0.9.0 실험도 이 명세를 유지했다.

- **절감 과대 추정:** 참조 절감액보다 최대 10% 높게 허용한다.
- **절감 과소 추정:** 참조 절감액보다 최대 20% 낮게 허용한다.
- 기존 최소 허용 금액 $1은 유지한다. 허용 구간 양 끝을 출력과 같은 센트 단위로 반올림한다. 참조 $56.94의 구간은 **$45.55~$62.63**이다. 모델이 낸 금액은 보정하지 않는다.
- 단가 각각의 대칭 10% 정확도와 오차 방향은 `rate_accuracy`로 따로 기록하며 절감액 합격을 막는 조건으로 쓰지 않는다. 절감액이 맞아도 전후 비용 추정은 틀릴 수 있다.
- 금액 산술·문맥·가정·계약 오류와 미산출 기준, 6건 × 10회와 95% 산출률 조건은 유지한다. 리전 불일치를 새 가격 허용 범위로 수용하지 않는다.
- 새 기준 재채점: v0.8.0 기존 방식 PASS 6, 가격표 방식 PASS 3·INVALID 3. v0.7.0 실제 3호출은 PASS 5·PRICE_DEVIATION 1이며 남은 A1/1은 절감 과대 추정 +13.85%다.

**아래 v0.8.0 이하 개별 라운드 요약은 실행 당시 대칭 기준의 이력이다. 해당 결과의 현재 기준 판정은 위 비대칭 재채점 보고서에서 확인한다.**

## 비교 대상과 사전 기준

현재 `spec.json` v0.2.0에 입력 지문, 기대 문맥, AWS 단가 스냅샷, 비대칭 허용 오차와 반복 수를 고정했다.
제품 목적에 따라 기준을 바꾸면 판·이유·재채점 범위를 기록하고 원자료와 이전 판정을 보존한다. 기준 변경으로 늘어난 PASS를 모델 개선으로 보고하지 않는다. 입력·출력에 필요한 정보가 남아 있으면 추가 모델 호출 없이 재채점한다.

- 입력: 기존 FinOps 요약 고정 세트 A1·A7·A11·A12·A14·A16, 각 10회.
- 범위: 서울 리전 `t3.xlarge → t3.medium`, `t3.large → t3.small` 두 조합.
- 참조 단가: 2026-09-15에 조회한 [AWS 공개 요금 파일](https://pricing.us-east-1.amazonaws.com/offers/v1.0/aws/AmazonEC2/20260910195514/ap-northeast-2/index.csv).
  파일 판은 `20260910195514`, 해당 요금 적용일은 `2026-09-01`이다. 선택한 SKU·RateCode도 spec에 남겼다.
- 기준 조건: Linux, Shared, OnDemand, 사전 설치 소프트웨어 NA, CapacityStatus Used, USD/Hrs.
  인스턴스 컴퓨팅만 월 730시간으로 비교한다. 스토리지·네트워크·세금·할인·CPU 크레딧 비용은 제외한다.
- 월 참조 절감액: `(0.208 − 0.052) × 730 = $113.88`, `(0.104 − 0.026) × 730 = $56.94`.
  이 값은 합성 단가를 쓰는 단위 테스트의 정답과 구분한다.

| 항목 | 현재 v0.2.0 판정 |
| --- | --- |
| 입력 세트·반복 수 | 지문 일치, 6건 각각 10회. 일부 프로브로 전체 기준선 승인 불가 |
| 단가 오차 | 현재·목표 단가 각각 참조 대비 ±10% 여부와 방향을 별도 진단. 절감액 PASS 조건에 포함하지 않음 |
| 월 절감액 오차 | 과대 추정 `max($1.00, 참조 × 10%)`, 과소 추정 `max($1.00, 참조 × 20%)`까지. 허용 구간의 양 끝은 센트 반올림 |
| 산술·대상·사양·리전·가정·근거 필드 | 모든 산출 건이 계약 통과 |
| 산출률 | 전체 60회 중 95% 이상. 미산출 사유는 UNAVAILABLE만 허용 |
| 잘못된 추정·후보 누락·그래프 실패 | 1건이라도 있으면 보류. 원인을 고친 뒤 다시 측정 |
| 반복 일치 | 진단값만 기록. 같은 값이 반복되어도 절감액 허용 범위를 벗어나면 실패 |

10%·20%는 이 실험의 사용자 결정에 따른 허용 오차이며 PM이 보장한 정확도나 AWS 가격 보장이 아니다.
근거 필드의 존재·계산·조건은 자동으로 확인하지만 자유 서술 전체의 의미를 검증했다는 뜻은 아니다.
실계측 뒤 각 조합의 근거 원문과 모든 오류 회차를 읽고, 가정과 모순되는 설명을 별도로 기록한다.

## 실행

모델 생성과 요약 판정은 기존 `scripts/finops_eval.py`, `scripts/finops_judge.py`를 재사용한다.
`savings_eval.py`는 생성된 JSON만 읽는다. 별도 모델 호출, 평가 단가의 모델 입력 주입, 런타임 요금 API 연동은 없다.

추천만 비교할 때는 [replay.py](replay.py)의 `replay_recommendation`에 저장된 요약과 호출 클라이언트를 전달한다.
기존 추천·출력 검증 노드를 재사용하며, 호출자는 라운드별 예산·중단 조건과 원자료 기록을 관리한다.
이 실행의 `execution_mode`는 `frozen_summary_recommendation_replay`이며 전체 그래프·새 요약 품질의 증거와 구분한다.

가격 전용 진단은 [isolation.py](isolation.py)의 `run_price_only`로 호출하고 `score_price_only_report`로 채점한다.
후보 선택·요약을 실행하지 않으므로 원자료에는 `response_status`와 절감 예상만 둔다.
`probe_passed`는 선택한 진단 케이스의 기준 충족이며 `service_baseline_evaluated=false`를 함께 기록한다.
가격·문맥·산술 채점은 통합 조건과 같은 `score_estimate`를 쓴다. v0.6.0 첫 라운드에는 거절된 추정의 상세 진단이 없으므로 후속 원인 분석 전에 계측 보완이 필요하다.

```powershell
# 호출 규모만 확인: API 호출 없음
uv run python scripts/finops_eval.py --case A1 --case A11 --repeats 1 --estimate

# 라운드별 모델·설정·호출 수·비용·시간을 보고하고 승인받은 후에만 실행
uv run python scripts/finops_eval.py --case A1 --case A11 --repeats 1 --json probe.json
uv run python scripts/savings_eval.py probe.json --out probe-savings.json

# 이전 단가 쌍 3호출 후보: 사전 확인만 수행, 모델 호출 없음
uv run python apps/core-api/ai/evaluation/savings/results/20260915-pair-candidate-validation-1/run_round.py

# 60실행 / 최대 180호출. 해당 라운드 승인 후에만 실행
uv run python apps/core-api/ai/evaluation/savings/results/20260915-pair-candidate-validation-1/run_round.py --execute-approved-round

# 최신 v0.9.0: 고정 입력·구현 사전 확인, 모델 호출 없음
uv run python apps/core-api/ai/evaluation/savings/results/20260915-v0.9.0-rate-only-1/run_round.py

# 완료된 v0.9.0의 원자료·채점·호출 기록 재검사, 모델 호출 없음
uv run python apps/core-api/ai/evaluation/savings/results/20260915-v0.9.0-rate-only-1/analyze.py
```

부분 프로브를 `savings_eval.py`로 채점하면 모든 숫자가 맞아도 `complete=false`, 종료 코드 1이다.
최종 출력은 원자료 SHA256·명세 SHA256·scorer 판·모델 스냅샷·프롬프트 판/지문·절감액 오차 방향·허용 구간·단가 진단·미산출율·반복 일치를 담는다.
네트워크/제공자 실패로 전량이 채워지지 않았을 때는 누락을 기록하고 승인된 재실행으로 완성한다.

## 회귀와 보관

- FinOps: 같은 최종 원자료를 기존 요약 기준선 절차로 판정한다. 이전 판과 짝 비교까지 끝나기 전 승인 스냅샷을 갱신하지 않는다.
- SecOps: 절감 예상은 FinOps 전용 출력 모델에 둔다. SecOps의 모델 입력 스키마는 기존과 동일하게 유지하고, 공유 저장·조회 계약의 영향은 `ai/tests/test_secops_graph.py`와 Dispatcher 통합 테스트로 확인한다.
- 결과 보관: 승인된 실계측을 수행하면 이 폴더의 `results/<날짜>-<판>/`에 원자료·채점 결과·모델 설정·비용·검토 결과·한계를 함께 둔다. API 키는 보관하지 않는다.
- 가격표는 평가용 스냅샷이다. 실제 서비스의 단가 원천으로 import하거나 자동 갱신하지 않는다. 대상 리전/유형 또는 가격 기준이 바뀌면 참조와 입력을 새 판으로 고정해 재측정한다.
- 이 6건 통과는 다른 리전·인스턴스군·예약/Spot·Windows·실제 청구액 정확도를 증명하지 않는다.

## 공개 응답 해석

원천은 `packages/schemas/savings.py`와 `schemas/api/incidents.py`의 `RecommendationItem`이다.
`GET /api/v1/incidents/{id}`의 `recommendations[].ai_savings_estimate`에 저장한 값을 반환한다.

- `ESTIMATED`: 소수 2자리 문자열 `amount`, 소수 6자리 문자열 단가와 구조화 `basis`.
  예: 서울 `t3.xlarge → t3.medium`, AI 단가 `0.208000 / 0.052000`이면 `amount="113.88"`.
- `UNAVAILABLE / MODEL_UNAVAILABLE`: 모델이 산출하지 못함. `amount=null`, `basis=null`.
- `INVALID`: 누락·계약 오류·서버 문맥 불일치 사유를 기록. `amount=null`, `basis=null`.
- 필드 전체 `null`: 기존 레코드 또는 절감 예상 대상이 아닌 조치. 조회 시 모델을 다시 부르거나 0으로 채우지 않는다.
- 요약 3줄·실행 `parameters`·서버 `display_parameters`와 별개다. 절감 예상만 실패하면 실행 후보와 승인 가능 여부는 기존 Guardrail 결과를 따른다.
- 요약·추천 호출이 실패하면 그래프 FAILED다. 세 번째 단가 호출의 전송·구조화 출력 파싱이 실패하면 후보는 보존하고 추정만 `INVALID / MISSING_ESTIMATE`로 남긴다. 수용된 응답의 의미·문맥 오류는 추정의 사유 코드로 구분한다.
