## 변경 후 검증

[최신 dev 반영·게시 전 검증](results/20260917-prepublication/report.md)에서
#358을 포함한 dev `65e47d8` 기준 **2,259 passed / 0 skipped**를 확인할 수 있다.
전체 테스트 실행 시 #347 Python 62개는 앞선 검증본과 동일했다. 이후 테스트 파일 말미의 빈 줄 한 곳만 정리했으며 AST는 동일하다.
[앞선 무료 검증](results/20260916-publication-cleanup/report.md)의 대표 저장·조회 6개 경로,
새 앱 조회 24회·조회 모델 호출 0회와 요청 지문 보존 결과를 유지한다.
dev 대비 추가 Ruff 진단은 0개이며, 기존 185개는 별도로 남아 있다.
이전 [cases 이관 보류 기록](results/20260916-cases-deferred-validation/report.md)과
[v1 정리·summary 이관 기록](results/20260916-v1-preparation/report.md)의 당시 수치는 유지한다.
v1 정리 기록의 Docker 로그 링크만 로컬 원본 보존 안내로 바꿨다.
입력 변환 `ai/evaluation/cases.py`의 구현 이동은 #353 병합 후 #324 재개 때 진행한다.

1. 구조·경로만 바꾸면 기존 승인 스냅샷과 단가 SDK 요청 지문을 유지하고, 관련 회귀 테스트와 저장·조회 경로를 무료로 확인한다.
2. 단가 프롬프트·출력 스키마·모델·입력 조건을 바꾸면 새 라운드에서 고정 세트의 산출률·가격 오차를 다시 평가한다.
   기존 자료를 새 버전의 통과 기록으로 이름만 바꿔 사용하지 않는다.
3. 요약·추천 요청이 바뀌면 [summary 재통과 절차](../summary/baseline.md)를 적용한다.
4. 원자료·실패 기록·usage·요청 지문과 실행 전 승인 범위를 새 디렉터리에 저장한다. 실제 모델 호출은 별도 승인 후 실행한다.

무료 대표 서비스 검증은 아래 명령을 사용한다. 로컬 PostgreSQL·LocalStack이 필요하며, SDK 응답은 대역이다.
새 출력 디렉터리만 허용하고 실제 모델 키를 읽지 않는다.

```powershell
uv run --no-sync python apps/core-api/ai/evaluation/savings/verify_service.py --out <새-결과-디렉터리>
```

현재 승인 예산은 A 2 + B 60 + 서비스 18 = **80/80회** 사용했다. v1 정리의 추가 유료 호출은 0회다.
현재 FE의 절감액 표시와 SSOT 갱신은 계약 리뷰 후 담당 후속 작업이며, v1의 생성·저장·조회 검증과 별도로 추적한다.
