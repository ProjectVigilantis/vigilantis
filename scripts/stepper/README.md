# stepper — 시연 · FE 관찰용 테스트 서버

명령 한 줄로 **DB · LocalStack · API · 대시보드(FE)** 를 띄운다. 그 뒤에는 명령을 하나 누를 때마다 서비스가 **한 칸씩만** 움직인다. 스캔 · AI 분석 · 조치 실행 타이머가 꺼져 있어서, 무대에서 타이머를 기다리거나 타이밍을 맞출 필요가 없다. 막히면 명령 하나로 빈 화면으로 되돌린다.

> 이 도구는 개발 스택(`docker compose up`) · 문서 절차로 띄우는 시연 스택(`docs/E2E_DEMO_SCENARIOS.md`)과 **별개의 스택**(`vigilantis-test`)을 쓴다. 그 스택들이 떠 있어도 건드리지 않는다.

---

## 처음 한 번만 — 준비

1. **Docker Desktop**을 켠다.
2. 저장소 루트에 **`.env`** 가 있어야 한다. 없으면 `.env.example`을 복사해 만든다. AI 분석(`analyze`)을 쓸 거면 `OPENAI_API_KEY`를 채운다.
3. 저장소 루트에서 의존성을 설치한다.

   ```powershell
   uv sync --locked --all-packages
   cd apps/web; npm ci; cd ../..
   ```

## 시연 — 다섯 걸음

모든 명령은 **저장소 루트**에서 친다. 명령이 길어서 PowerShell 창마다 아래 한 줄을 먼저 치면 편하다(창을 닫으면 사라진다).

```powershell
function stepper { uv run python scripts/stepper/cli.py @args }
```

| # | 명령 | 무슨 일이 일어나나 | 화면 |
| --- | --- | --- | --- |
| 1 | `stepper up` | DB · LocalStack · API를 띄우고 FE 창을 연다. 처음이면 1–3분 걸린다 | — |
| 2 | (자동) | FE가 준비되면 **브라우저가 저절로 열린다** | 자산 · 인시던트가 **비어 있는** 첫 화면 |
| 3 | `stepper collect` | 가짜 AWS(LocalStack)에서 자산 16건을 수집한다 | 1–2초 뒤 **자산이 화면에 붙는다**(새로고침 불필요) |
| 4 | `stepper inject ssh` | 서버 `vigilantis-seed-idle`에 SSH 무차별 대입 공격 1건을 넣는다 | 보안 관제에 **위협 인시던트가 '분석 중'으로** 뜬다 |
| 5 | `stepper reset` | 전부 지우고 2번 상태로 되돌린다(FE 창은 그대로) | 끝나면 **브라우저를 새로고침**한다 — **빈 화면**에서 다시 3번부터 |

끝나면 `stepper down` — FE 창을 닫고 서버를 내린다.

**시연 전에 `stepper reset`을 한 번 한다.** 이전 버전으로 띄워 둔 서버가 남아 있으면 `up`은 그 서버를 그대로 쓰는데, 그 서버는 코드 변경을 다시 읽지 않는다(`collect` 뒤 화면이 붙지 않을 수 있다). `reset`이 지금 코드로 다시 띄운다.

**`reset` 뒤에는 브라우저를 새로고침한다.** FE는 끊긴 연결을 점점 길게 기다리며 다시 붙어서(최대 30초), 새로고침하지 않으면 빈 화면으로 바뀌기까지 한참 걸릴 수 있다.

**같은 폴더에서 `npm run dev`를 따로 켜 두지 않는다.** Next는 폴더마다 개발 서버를 하나만 띄워서, 포트가 달라도 이 도구의 FE가 뜨지 않는다. 그 창에서 `Ctrl+C`로 끈 뒤 `stepper up`을 한다.

**4번에서 '분석 중'을 넘어가려면** `stepper analyze`를 누른다. AI가 판단 근거와 추천 조치를 붙여 카드가 **'승인 대기'** 로 바뀐다. **이것만 OpenAI 과금이 있다**(아래 §과금).

**3번과 4번은 순서가 있다.** 4번은 대상 서버가 수집돼 있어야 해서, 3번 전에 누르면 "자산이 없다"며 넣지 않는다.

### 명령마다 나오는 안내

명령을 누르면 세 가지를 출력한다 — ① 방금 한 일 ② **FE에서 볼 곳** ③ **다음에 할 수 있는 것**. 다음에 뭘 할지 모르겠으면 `stepper status`를 친다.

```text
[collect] 자산·메트릭 수집·적재(판정·카드 없음) (4.99초)
  리전 ap-northeast-2 자산 16건 · 미수집 유형 alb_target_groups, auto_scaling_groups
  FE 연결 2개를 끊어 재조회를 일으켰다
FE에서 볼 곳: 자산 — 서버가 WebSocket을 끊어 FE가 재연결하며 목록을 다시 불러온다(1–2초. 카드는 생기지 않는다)
다음에 할 수 있는 것:
  - scan — 판정으로 FinOps 카드를 만든다
  - inject ssh — 로그 근거가 붙은 SSH 관측 1건(C01 · vigilantis-seed-idle)
```

> `미수집 유형 alb_target_groups, auto_scaling_groups`는 정상이다 — LocalStack 무료판에 그 서비스가 없다(ADR-0006).

## 과금 — OpenAI는 `analyze`에서만 쓴다

| 명령 | OpenAI | 과금 |
| --- | --- | --- |
| `up` · `reset` | 키가 맞는지 확인만 한다(모델 정보 조회) | 없음 |
| `collect` · `scan` · `inject` · `dispatch` · `status` | 안 씀 | 없음 |
| **`analyze`** | 분석 대기 카드마다 실제 모델 호출 — FinOps 서버 3회, 그 밖의 FinOps 2회, 보안 3회 | **있음** |

`analyze`는 누르기 전에 **예상 호출 수를 보여 주고 `y`를 받는다**(`-y`를 붙이면 묻지 않는다). 띄워 두기만 해서는 과금되지 않는다.

## 명령 전체

| 명령 | 하는 일 |
| --- | --- |
| `up` | 서버와 FE를 띄우고 브라우저로 연다. 서버가 이미 떠 있으면 **데이터를 그대로 쓴다**(빈 화면부터 하려면 `reset`). `--no-web`이면 FE 없이 |
| `reset` | 서버 데이터를 전부 지우고 처음 상태로 준비한다. 이 도구가 띄운 FE는 그대로 둔다 |
| `down` | FE 창을 닫고 서버를 내린다(데이터 삭제). 기록은 남는다 |
| `status` | 지금 인시던트 · 실행 상태, FE 주소, 다음에 할 수 있는 것 |
| `collect` | 자산만 수집한다. 인시던트는 만들지 않는다 |
| `scan` | 수집 + 판정까지 한다. 비용 후보 · 미사용 자원이 **자산 인시던트 카드 3장**으로 생긴다('분석 중') |
| `inject ssh` | SSH 공격 1건을 넣는다. 기본은 사례 `C01` · 대상 `vigilantis-seed-idle`. 바꾸려면 `--case C01`–`C07` · `--target <서버 이름>` |
| `inject golden <파일> --target <이름>` | 테스트용 골든 위협 입력(`datasets/golden/secops/input`) 1건을 넣는다 |
| `analyze` | '분석 중' 카드 전부를 AI로 분석한다 → '승인 대기' 또는 '진행 불가'. **과금** |
| `dispatch` | 진행 중인 조치 실행을 한 칸 진행한다. 차단이 끝났으면 해제 후보를 낸다 |
| `dispatch --fail-status-check <이름>` | 다음 칸에서 서버 기동 확인(Status Check)이 **일부러 실패**하게 만든 뒤 진행한다 — 자동 원복 장면용 |

- 승인 · 실행 · 해제 · 종료 판단은 **FE 화면에서** 누른다. 그 화면이 보여 줄 대상이다.
- 명령은 한 번에 하나만 돈다. 처리 중에 또 누르면 "다른 버튼을 처리하고 있다"며 거부한다.
- `inject`는 누른 시각을 관측 시각으로 써서, 같은 명령을 다시 눌러도 새 인시던트가 생긴다.

## 흐름 예시 — 조치까지 보여 줄 때

서버 이름은 시드 자산 이름이다. 모델 호출 수는 재시도가 없을 때의 값이다.

**T1 — 서버 사양 줄이기 실패와 자동 원복**

1. `reset` → `scan` → `analyze`(카드 3장 · 7회 과금)
2. FE 자산 관제 「인시던트」 탭의 「승인 대기」에서 `vigilantis-seed-idle-dev` 카드 [조치 실행] → [실행]
3. `dispatch --fail-status-check vigilantis-seed-idle-dev` — 사양 변경 실행, 주입기가 기동 직후 서버를 멈춘다
4. `dispatch` 세 번 — 기동 확인 실패 → 자동 원복 접수 → 원복 실행
5. FE 인시던트 상세 「수행된 조치」에서 **'복구 완료'** 배지를 본다

**T2 — SSH 공격 차단과 해제**

1. `inject ssh` → `analyze`(3회 과금)
2. FE 상세 [승인하고 차단] → [실행] → `dispatch` — 차단이 끝나면 해제 후보가 선다
3. FE [승인하고 해제] → [실행] → `dispatch` → FE [종료 판단]

**화면을 볼 때** — 카드 배지와 「수행된 조치」의 실행 배지는 새로고침 없이 바뀐다. 보안 인시던트 목록의 「승인 대기 N」 칩과 T1 원복 안내 패널(상세를 떠나면 사라진다)은 그렇지 않으니 카드 배지와 「수행된 조치」를 본다. 알림은 명령을 누를 때 열려 있던 화면에만 뜨므로 **볼 화면을 먼저 열어 두고** 누른다.

## 막혔을 때

| 이런 메시지가 나오면 | 이렇게 한다 |
| --- | --- |
| `db 5432번 포트를 다른 프로그램이 쓰고 있어 5433번으로 띄운다` | 문제 아니다 — 다른 스택이 쓰는 번호를 피해 옆 번호로 띄운 것이다. FE 주소도 출력에 나온 대로 연다 |
| `중단: … 포트 …–…이 모두 사용 중` | 안 쓰는 스택을 내린다(`docker ps`로 확인) |
| `중단: 테스트 서버가 떠 있지 않다` | `stepper up` |
| `중단: 다른 스택이 테스트 서버 포트를 쓰고 있어` | 서버가 뜬 뒤에 다른 스택이 그 포트를 차지했다. `stepper reset`하면 빈 번호로 옮긴다 |
| `중단: 지금 테스트 서버는 다른 체크아웃에서 띄웠다` | 다른 폴더(worktree)에서 띄운 서버다. 그 폴더에서 쓰거나, 여기서 `stepper reset` |
| `중단: … 토큰을 받지 않는다` · `회차 기록이 없다` | `stepper reset` |
| `! 모델 키 확인 실패` | `.env`의 `OPENAI_API_KEY`를 고치고 `stepper reset`. 그대로 두면 `analyze`가 실패한다 |
| `! FE를 띄우지 않았다 — apps/web에서 npm ci` | `cd apps/web; npm ci` 뒤 `stepper up` |
| `! FE를 띄우지 않았다 — …번 포트를 다른 프로그램이 쓰고 있다` | `stepper reset`하면 빈 번호로 옮긴다 |
| `! FE를 띄우지 않았다 — 이 체크아웃에서 다른 next dev가 돌고 있다` | 같은 폴더에서 따로 켠 `npm run dev`다. 그 창에서 `Ctrl+C`로 끈 뒤 `stepper up`. 그 FE를 그대로 쓰려면 `--no-web` |
| `FE: 주소가 바뀌어 다시 띄운다` | 문제 아니다 — 기록된 포트를 다른 프로그램이 차지해 서버가 옮겨 가서, 옛 주소를 보던 FE를 닫고 새로 띄운 것이다. 새로 열린 브라우저 탭을 쓴다 |
| `'…' 자산이 없다 — collect나 scan을 먼저` | 3번(`collect`)을 먼저 누른다 |
| 화면이 전부 조회 오류 | 출력에 나온 FE 주소(`localhost:…` 또는 `127.0.0.1:…`)로 연다. 다른 포트로 열면 서버가 막는다 |
| FE 창을 실수로 닫았다 | `stepper up` — 서버는 그대로 두고 FE만 다시 띄운다 |

## 더 알아보기

### 어떻게 돌아가나

- **테스트 서버**: `docker-compose.yml` 위에 `compose.override.yml`을 얹어 compose 프로젝트 `vigilantis-test`로 띄운다. 타이머와 모의 위협 파일 소비 루프를 끄고, 포트는 이 노트북(`127.0.0.1`)에만 연다.
- **단계 진행 라우터**(`app.py`): 제품 앱에 `/_stepper/*`를 붙인다. 명령 하나가 앱의 주기 함수를 1회 부르고, 그 결과가 같은 프로세스의 WebSocket으로 FE까지 간다. `collect`는 WebSocket 이벤트가 없어서, 끝나면 연결을 한 번 끊어 FE가 재연결하며 다시 조회하게 한다.
- **CLI**(`cli.py` · `server.py`): 서버와 FE를 띄우고 내리며, 명령마다 안내를 출력한다.
- **FE**: `npm run dev -- -H localhost -p <FE 포트>`로 띄운다(`-H localhost` — 같은 망의 다른 기기에서 테스트 화면이 보이지 않게). Windows는 새 창이고, 그 밖의 OS는 백그라운드로 떠 출력이 `~/.vigilantis/stepper/web.log`에 쌓인다.

### 포트와 안전장치

- **띄울 때** 기본 번호(db 5432 · localstack 4566 · api 8000 · FE 3000)를 다른 스택이나 프로그램이 쓰고 있으면 **+1씩 비켜 간다**(최대 +9). 남의 스택은 멈추거나 내리지 않는다. 고른 번호는 `~/.vigilantis/stepper/state.json`에 남고, 다음 `reset`은 **기록된 번호를 먼저 다시 고른다**(기본 번호가 그사이 비었어도 옮기지 않아 떠 있는 FE의 주소가 그대로다). 시드 · 실패 주입기 · API 호출 · FE의 API 주소 · CORS 허용 출처가 전부 그 번호를 따른다.
- **떠 있는 서버에 명령할 때**는 기록된 포트를 남이 잡고 있으면 아무것도 하지 않고 거부한다. 시드는 LocalStack의 NACL 규칙을 비우고 실패 주입기는 서버를 멈추므로, 남의 스택에 닿으면 그 스택을 망가뜨리기 때문이다.
- `down`은 기록한 FE의 PID와 **프로세스 생성 시각**이 둘 다 맞을 때만 그 창을 닫는다. 창을 직접 닫아 PID가 다른 프로세스에 넘어갔으면 닫지 않고 기록만 지운다.
- 띄우기 전에 `docker compose config` 결과에서 포트가 전부 `127.0.0.1`인지, 볼륨이 이 프로젝트 것인지 본다.
- 서버 진입점은 타이머가 켜졌거나, 토큰이 없거나, AWS 주소가 LocalStack이 아니면 뜨지 않는다.
- 초기화는 볼륨째 한다. LocalStack은 재시작하면 비므로 DB만 남기면 같은 서버의 카드가 이중으로 생긴다.

### 기록

- 회차는 `reset`부터 다음 `reset`까지다. 기록은 `~/.vigilantis/stepper/rounds/<회차 ID>/`에 남는다(`--data-root`로 위치를 바꾼다).
  - `steps.jsonl`: 명령마다 한 줄 — 서버 보고, 누르는 동안 받은 WebSocket 이벤트, 누른 뒤의 API 상태
  - `inputs/`(주입한 입력 파일) · `seed.log` · `inbox/`(다음 초기화 때 옮겨 온 소비 결과)
- 서버 토큰은 `~/.vigilantis/stepper/token`에만 있고 출력 · 기록에 남지 않는다.

### 주의

- 서버를 **기본 포트로** 띄운 채 pytest를 돌리지 않는다 — 테스트가 이 서버의 DB · LocalStack에 붙는다.
- OpenAI 한도는 키가 아니라 조직 · 프로젝트 단위라, 같은 조직의 키를 쓰는 다른 작업과 한도를 나눠 쓴다.
- CLI의 WebSocket 클라이언트(`websockets`)는 직접 선언한 의존성이 아니라 `uvicorn[standard]`를 통해 설치된다.

### 유지 · 보장 범위

- 서비스 흐름 밖의 도구라 제품 동작이 바뀔 때마다 함께 고치지 않는다. CI는 이 도구 자신의 로직과 안전장치만 본다 — 쓰기 전에 `reset` → `scan`을 한 번 돌려 본다.
- 흐름 예시 · 예상 모델 호출 수는 이 도구를 만든 시점 기준이다. 실제와 어긋나면 그때 고친다.
- 이 도구가 **주장하지 않는 것**: FE 표시(사람이 화면에서 본다) · 실 AWS 권한과 동작(LocalStack 변화다) · 모델 판단 근거의 품질 · 타이머끼리 섞이는 실제 동작(앱 타이머로 도는 시연 · 리허설에서 본다).
